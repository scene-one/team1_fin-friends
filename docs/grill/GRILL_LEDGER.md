### S2 — 출석체크 ⭐ 지급 조건 *(2026-09-01)*

### S4 · P1 — 미션 사진 인증과 아동 이미지 정책 *(2026-09-01 · 동시 해소)*

**검증 장치** 스토리지에 미션 이미지 객체 0건 · 스키마에 이미지 참조 컬럼 부재.

**P-05가 구조적으로 지켜진다** 동의 → 등록 → 링크 순서라 **동의 없이는 진입할 링크 자체가 존재하지 않는다.** 화면에서 막는 게 아니라 자격이 발급되지 않는 방식.

**남은 기술 확인** 스토어 경유 후 링크 컨텍스트 유지(deferred deep link) 플랫폼 지원 여부 → O6에서 검증.

### C1 — 1차 타깃 세그먼트 *(2026-09-01)*

**결정** **H2형(아날로그 가정)** 을 1차 타깃으로. H1형(경쟁사 이탈)은 2차 — 배제가 아니다.

**근거** ① 이번 세션의 결정들(봉투형·앱 2개 분리·초대 링크)이 **이미 H2를 겨냥해 정렬**돼 있어, H1형을 고르면 그 근거가 함께 무너진다 ② H1형 시장은 아이부자 0원·계좌카드형 83.9% 점유로 **가격 축이 봉쇄**돼 있다(R7) ③ H2형의 *"볼 것이 없다"* 는 미충족 수요다.

**받아들인 대가** ① 규모 추정이 어렵다 — 29.3만이 H2형만의 규모인지 두 집단 합인지 **미분해** ② **온보딩 부담이 가장 큰 집단을 골랐다**(C4 최저점 위에 앱 설치) ③ 퍼핀 대비 우위 서사가 약해지고 **주 비교 대상이 현금 봉투**가 된다.

**검증 경로** 세그먼트 분해·규모 확정은 C4(고객 인터뷰)에서. 그전까지 29.3만은 `[가설]`.

### C3 · C6 · C10 — MINOR 3건 직접 결정 *(2026-09-01)*

사용자 지시로 MINOR는 묻지 않고 결정 후 보고한다(CLAUDE.md 「사람에게 묻는 기준」).

**C3 아동 화면 % 표기** → 아이 화면에 `%` 미노출. **채움 게이지 + 개수**(*"10칸 중 3칸"*). `%`는 초6 과정이라 타깃 연령이 못 읽는다. 부모·설계 문서는 `%` 유지. 대가: 부모와 아이가 다른 숫자를 본다 → **분모 10 고정**으로 환산을 자명하게.

**C6 이자 주기** → **주 단위**. 달력이 초2-2에 처음 등장하므로 월 단위는 타깃 연령 절반이 「이번 달」을 못 잡는다. 대가: 부모 조작 4배 → **자동 지급 기본값**으로 상쇄하고, C5 검증과제에서 주/월 부담을 함께 묻는다.

**C10 갈래 B 이탈 방지** → ⭐를 붙이지 않고 **회고를 다음 봉투 배분의 입구**로 만든다. 붙이는 순간 갈래 A·B 구분이 무너진다. 보상이 아니라 **효용**으로 연다. 대가: *"넘겼으니 예산을 늘려라"* 로 읽힐 수 있어 **증액을 권하지 않는 중립 문구**로 제한. 4주 실측에서 70% 미달이면 재검토.

### C2 · C4 · C5 · C8 · C9 — 고객 관점 5건 *(2026-09-01)*

**C2 대상 연령** → **초1~3(만 7~9세)**. 이번 세션의 결정 다수(% 미노출·주 단위 이자·중간마디 유보)가 인지 발달 단계를 근거로 내려졌으므로 범위를 못 박지 않으면 근거가 흔들린다. 난이도 정의표가 초4까지 덮어 상단 여유 한 학년. 넓히지 않은 이유 — 제작량(O1)·아바타가 초5~6에 유치·초1은 첫 용돈 시점이라 못 버림. **대가**: 시장이 좁아지고 모집단 감소(R6)가 곱해진다. 초4 이탈 → R8.

**C9 난이도 설정** → **부모에게 단계를 묻지 않고 학년을 묻는다.** 정의표의 「대상」 행이 이미 학년 기준이라 자동 매핑 후 조정 슬라이더 제공. H2의 최저점이 C4(온보딩 비용)라 **판단을 요구하는 질문을 줄이는** 것이 핵심. 진단 퀴즈 배치는 단계를 더하므로 기각. **대가**: 학년은 근사치라 한글 해득 편차를 못 잡는다 → 슬라이더 필수.

**C4 인터뷰 계획** → **β 클로즈드 8슬롯과 같은 코호트**로 묶는다. 8명(H2형 6 · H1형 2) · 입주 직전 + 4주 후 전후 2회 · **월 초 가입 정렬**(주기 초기화가 E4·E1을 오염시키지 않도록). PRD의 「계측 먼저, 인터뷰 나중」 순서를 지키면서 4인 팀이 리크루팅을 두 번 돌지 않는다. **대가**: n=8은 *"이 설계가 통하는가"* 는 답해도 *"시장이 얼마인가"* 는 못 답한다. `raw/10-market/` 이 비어 있다.

**C5 부모 이자 의향 검증** → C4 인터뷰 필수 문항으로. 🔴 **의향이 아니라 행동을 잰다** — 전후 2회로 *"주겠다"* 와 *"줬다"* 의 간극을 대조. 주/월 부담도 함께 물어 C6 결정을 검증. FAIL(≤2/8)이면 부모 적금 구조 자체를 재설계.

**C8 아이 Pain → 부모 화면** → **봉투형이 R8을 부분 해소했다.** 건별 카드는 아이가 적어야 데이터가 생겼지만 봉투는 결제만으로 자동 대조되므로, C5(사전 개입 사각지대)가 *"간식 봉투를 넘겼다"* 로 부모 화면에 나타난다. **그러나 해소가 아니다** — 새 신호는 소비 계열 2건뿐이고 나머지 10건은 그대로다. **아이 인터뷰 0건이 남은 최대 공백**이며, C4의 8명은 부모다.

### C7 — 부모 적금 이율 *(2026-09-01)*

**결정** 연 20%를 사양으로 박지 않는다. **부모가 설정**하고 우리는 기준선(시중 3.40~7.00% `[A]` · Greenlight 19.84% `[A]`)을 옆에 둔다. 기본값 연 10%는 `[가정]` 등급으로 명시.

**근거** *"아이가 배운 이율이 현실의 3배면 잘못된 기준선을 심는다"* 는 문제는, 우리가 숫자를 박는 순간 **우리 책임**이 된다. 부모가 정하면 *"우리 집의 약속"* 이지 *"금융 상식"* 이 아니다. 잘못된 기준선을 막는 진짜 장치는 이율을 낮추는 게 아니라 **화면에 시중 실측치를 함께 두는 것**이다.

**아이 화면 표기** C3(% 미노출)과 일관되게 **정액 비례 표현** — *"10,000원을 모으면 한 달에 100원"*. 시중 비교도 같은 형식이라 비율을 모르는 아이도 **두 수를 비교**할 수 있다.

**받아들인 대가** ① 부모마다 달라 학습 내용이 균일하지 않다 → **퀴즈는 이율을 정답 근거로 쓸 수 없고 시중 실측치만 인용**한다 ② 기본값 10%는 근거 없는 `[가정]` → C5 인터뷰에서 실제 설정값을 물어 대체 ③ 부모가 0%로 두면 실천 동기가 사라진다 → 하한 강제 없이 안내만.

### O6 · O8 — 기술 스택과 결제 트랙 *(2026-09-01)*

**O6 기술 스택** → **PWA(웹 기반).** three.js가 브라우저 네이티브라 브릿지가 없고, **S12 초대 링크가 설치 없이 바로 연결**되며, 앱 2개를 경로/서브도메인 분리로 한 코드베이스에서 낸다. 스토어 심사가 없어 β 4주 중 당일 수정이 가능하다.

- **되돌린 것** — S9 앱 2개 분리의 근거 ②(*"P-05 차단을 빌드 단위로 검증"*)가 웹에는 없다. **오리진 분리 + 서버 스코프 강제**로 대체하고, 검증을 *"아이 오리진 번들에 부모 엔드포인트 0건"* + *"아이 토큰으로 부모 API 403"* 으로 재정의했다.
- **받아들인 대가** ① 🔴 **부모 신뢰도** — 스토어에 없는 서비스에 아동 금융 정보를 맡길까. 1차 타깃이 아날로그 가정이라 특히 위험하다 `[가정]` → C4에서 물어야 한다 ② iOS 웹 푸시 제약 (F11 도달률) ③ 저사양 안드로이드 3D 성능 ④ 오프라인 중복 지급 방지를 Service Worker로 직접 구현.
- **함께 정한 것** 외부 CDN 미사용 · 정적 자산 자체 호스팅(→ P5).

**O8 제휴사** → **제휴 없이 먼저 만들고 β는 모의 결제로.** 협상은 병렬, **β 결과를 협상 카드로** 쓴다. 봉투형이 제휴사 한도 API 의존을 없앤 덕에 가능해졌다.

- 🔴 **못 재는 것** — **업종 매칭 정확도(≥90%)**. 이건 봉투형의 최대 리스크였고(틀리면 아이가 안 쓴 봉투에서 돈이 빠진다) 그 검증이 제휴 이후로 미뤄진다. **WPA 실천 트리거 5(소비 회고)도 모의 기반**이라 v1 3종 중 1종이 모의 데이터다.
- ⚠️ β 결과 인용 시 실측과 🧪`[모의]`를 반드시 구분한다.
- **가맹점 분류 상세도는 협상 항목이 아니라 선정 기준**이다 — 봉투형의 성립 조건이므로.

### O1~O5 · O7 · O9 · O10 — 운영 관점 나머지 8건 *(2026-09-01)*

**O1 제작량** → **3단계만 출시**하고 3 → 2·4 → 1·5 확장. 「지문 3종 × 숫자 변형 5종」. 3단계 대상(초2-2~초3-1)이 1차 타깃 초1~3의 한가운데이고 금감원 교재 기준선에 가장 가깝다. 🔴 **대가 — C9와 부딪힌다**: 초1 가정은 자동 매핑이 1·2단계를 가리키는데 콘텐츠가 없다. 온보딩에서 *"준비 중"* 을 명시하고 β는 초2~3으로 모집해 회피.

**O2 제작·검수** → 팀이 쓰고 **금감원 교재 2종을 검수 기준선**으로. 🔴 비전문가가 아동 학습 콘텐츠를 쓴다는 사실을 감추지 않는다. 방어선이 외부 기준선 하나뿐이고 그 교재는 초3·4학년용이라 **1·2단계엔 대조 기준이 없다** — O1의 3단계 우선이 이 위험도 줄인다.

**O3 승인 병목**(MINOR) → 24h 리마인드 · **72h 자동 만료**. 만료 표시는 「승인되지 않음」이 아니라 **「확인하지 못했어요」**. 🔴 **만료를 「미실천」으로 집계하지 않되 WPA 분모에서도 빼지 않는다** — 빼면 승인 병목이 지표에 안 잡힌다.

**O4 사진 운영**(MINOR) → **부담이 거의 없다.** P-13 확장(서버 무저장)으로 보관·파기·유출 정책이 애초에 생기지 않는다. 남는 건 신고 경로 1건, 그것도 **이미지가 아니라 신고 사실만** 기록.

**O5 온콜**(MINOR) → 사람이 지켜보지 않는다. 규제 계층은 **알림과 동시에 자동 차단**. 별 원장 불일치는 **지급을 멈추지 않고 기록만 격리**(아이가 잃는 경험을 만들지 않는다). β는 수동 점검으로 충분하되 **자동 차단 구현을 일반 공개 게이트에 넣는다** — 없으면 30분 SLA는 문서에만 있는 숫자다.

**O7 β 모집** → 8가정 · H2형 6 · H1형 2 · **초2~3 한정**(O1) · **월 초 정렬**(S8) · 4주 · **중도 이탈 대체 없음**(분모 8 고정). 🔴 조건이 셋이라 채우기 어려울 수 있다 — 풀어야 하면 **월 초 정렬을 먼저** 푼다(유일하게 운영 보정 가능).

**O9 CS**(MINOR) → **부모 경유 원칙.** 아이 화면에 문의 진입점을 두지 않는다 — 아동이 직접 개인정보를 제출하는 경로를 만들지 않기 위해서. 대가: R8(아이 신호 0건)이 CS에서도 반복된다.

**O10 WPA 판정 운영**(MINOR) → D+1 자동 산출 · 제품 담당 1인이 매주 고정 요일 · −10%p 알림 · 2주 연속이면 로드맵 재검토. 🔴 **β WPA는 트리거 5가 모의 기반이므로 모의 비중을 함께 기록**한다.

### R1~R10 — 수익모델 관점 10건 *(2026-09-01)*

**신규 페이지** `wiki/concepts/business-strategy/수익-구조.md` — 리스크 R5(*"수익 산출식이 없다"*)를 닫는다.

**R3 무료 유지** → **확정.** 아이부자 0원·계좌카드형 83.9%로 가격 축이 봉쇄됐고(R7), 1차 타깃이 아날로그 가정이라 지불 장벽이 치명적이다. 🔴 **대가 — 수익이 전적으로 제휴사에 종속**되고, PWA라 스토어 결제 경로조차 없어 **대체 수익원이 구조적으로 막혀 있다.**

**R1 수익 산출식** → **가정 구간을 명시한 범위 모델.** 모든 수치 `[가정]` 등급.

🔴 **계산이 드러낸 것 — 결제 수수료는 수익원이 아니다.** 기본 구간에서 **가정당 월 75원**이다. 1차 타깃 29.3만을 **전부** 확보해도 월 2,200만원이고, 현실적 초기 규모(수천 가정)에서는 월 수십만 원이다.

> [[핀프렌즈]]가 *"결제 수수료 + 제휴 **2중 구조**"* 라고 서술해 온 것은 **두 축이 비슷한 크기라는 인상**을 주는데 사실이 아니다. ①은 보조 축이고 **수익 성패는 ②(제휴 보상) 하나에 달려 있다.**

**R2 수수료율** → 협상 확인 사항에 **발급 건당 보상 단가**를 추가. 결정적인 것은 수수료율이 아니다.

**R6 제휴 수익 형태** → **선불수단 발급·사용에 붙는다. 예적금 가입에 붙지 않는다** — P-20과 S7의 ⭐ 잠금 때문에 예적금 계좌 개설은 수익원이 될 수 없다. 잔액 예치 이자 배분은 선불충전금 100% 별도관리 제약으로 여지가 작다.

**R5 손익분기** → 🔴 **산출 불가로 남긴다.** ② 단가가 미확인이라 지배 변수가 비어 있다. **억지로 내지 않는다** — 근거 없는 숫자가 문서에 박히면 나중에 인용된다.

**R10 수익 시점** → 제휴 계약 체결 이후. β(모의 결제) 기간은 **수익 0**.

**R4 실물 카드**(MINOR) → **MVP는 발급하지 않는다.** F16 카드 없는 체험으로. 형태·비용은 제휴 계약에서.

**R7 진입 속도**(MINOR) → 모집단 연 5~12% 감소 + 연령 축소로 곱해진다. **β 4주를 늘리지 않는다** — 게이트 미달 시 기간 연장이 아니라 **범위를 줄여 재판정**.

**R8 졸업 설계** → **연령 상한을 강제하지 않는다.** 콘텐츠 소진(5단계 = 초3 상위~초4) 후 자연 이탈. 체류 최대 3~4년. 🔴 **LTV가 체류가 아니라 콘텐츠 길이로 정해진다** — 상급 학년 확장은 O1이 이미 감당 못 한다고 판정한 축이라 **수익 확인 이후의 문제**다.

**R9 광고**(MINOR) → **영구 배제.** 아동 대상 광고 규제 위험 + 두 가치 선언과 정면 충돌. 옷장 아이템 현금 판매도 P-01·P-21(별↔현금 분리) 충돌로 배제.

### P3~P10 — 규제 관점 8건 *(2026-09-01)*

**P3 보존·파기** → **탈퇴 즉시 파기.** 식별 가능한 모든 것을 지우고 **비식별 집계치만** 남긴다.

🔑 **즉시 파기가 가능한 이유는 선불업 B안의 배당금이다.** 전자금융거래법 거래기록 보존 의무는 **발행사(제휴사)** 에 있고 우리는 발행사가 아니다. **그래서 결제 내역 사본을 보관하지 않고 조회만 한다** — 사본을 들면 그 순간 법정 보존 대상이 되어 즉시 파기가 불가능해진다. ⚠️ **이것은 설계 제약이다**: 성능·오프라인을 이유로 결제 내역을 캐시하고 싶어질 때 이 결정이 먼저 무너진다. 캐시는 **세션 범위·서버 미저장**만 허용.

**P4 동의 철회**(CORE) → 철회 시 아이 오리진 즉시 차단 + 파기 + **미사용 초대 링크 전부 무효화**. **주기적 재확인은 두지 않는다**(형식적 동의만 늘린다). 1년 미접속 → 휴면 → 통지 → 30일 뒤 파기.

**P7 탈퇴**(CORE) → 선불 잔액은 **전액 환불**(P-11, 발행사가 처리) · ⭐는 **환불 대상 아님**(현금이 아니고 전환 경로가 코드에 없다) · 나무·숲은 파기. 🔴 **탈퇴 화면에 미리 명시** — *"모은 별과 나무는 되돌릴 수 없어요"* 확인 후에만 진행.

**P5 외부 연동**(CORE) → **국외이전 없음.** PWA에서 정한 외부 CDN 미사용을 분석 도구까지 확장. 제3자 오리진 요청 **0건**을 CSP로 강제.

**P6 선불충전금 표시**(MINOR) → 잔액 화면에 **발행사명 명시**. 별도관리는 발행사 의무이고 우리는 고지한다. 🔴 **봉투 합계와 실제 잔액이 어긋나면 실제 잔액이 기준** — 봉투는 회계가 아니라 계획이다.

**P8 고지 문구 검수**(MINOR) → 정책 담당이 쓰고 **학습 난이도 3축을 그대로 적용해 검수**한다 — 고지문도 학습 콘텐츠와 같은 기준으로 읽혀야 한다. 출시 전 최소 1회 · `%` 금지.

**P9 부모 적금 법적 성격**(CORE) → **우리가 자금을 수취하지 않는다.** 앱은 계산해 보여줄 뿐이고 실제 이동은 부모가 아이 지갑에 충전하는 행위다. 예치 후 우리가 지급하는 구조는 **금지**. ⬜ *"표시만 해도 금융상품 유사 표시인가"* 는 미확인 → **F15 ⭐ 잠금 해제 게이트에 P-20 검토와 함께** 올린다. 「적금·이자·금리」 용어도 같은 게이트에서 검토.

**P10 지오펜싱 회수**(MINOR) → **위키 내 잔존 서술 0건 확인.** 인용 금지 목록에 등재돼 있고 P-19는 적용 대상 소멸로 기록됨. ⚠️ 위키 밖(발표 자료) 회수는 보증할 수 없다.
