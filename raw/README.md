# raw/ — 원본 자료 보관소 (사람 전용 · LLM 수정 금지)

이 폴더는 **진실의 원천(source of truth)** 입니다. 사람이 수집해 넣고, LLM은 **읽기만** 합니다.
LLM이 만든 요약·해석은 전부 `wiki/` 로 갑니다. 원본은 절대 편집·요약·삭제하지 않습니다.

## 카테고리

| 폴더 | 담는 것 | 예 |
|---|---|---|
| `00-inbox/` | **분류 전 임시 유입.** 넣자마자 여기, 수집(ingest) 시 카테고리로 이동 | 방금 클리핑한 기사 |
| `10-market/` | 시장 규모·산업 통계·설문 원자료 | 윤선생 학부모 설문, Dataintelo 시장 리포트 |
| `20-services/` | 경쟁·유사 서비스 원문 | 퍼핀 공식 사양, 아이부자 소개, 카카오뱅크 mini 보도 |
| `30-research/` | 학술 논문·메타분석·실험 | 금융교육 메타분석, 게이미피케이션 효과 연구 |
| `40-regulation/` | 법령·규제·감독 가이드라인 | 전자금융거래법, 미성년자 계약 관련 |
| `50-user-voice/` | 리뷰·인터뷰·설문 **응답 원자료** | 앱스토어 리뷰 CSV, JTBD 인터뷰 녹취 |
| `60-internal/` | 팀 내부 산출물의 **원본 스냅샷** | 발표덱, 기획서 확정본 |
| `70-tech/` | 기술·구현 참고자료 | API 문서, 프레임워크 가이드 |
| `90-misc/` | 어느 카테고리에도 안 맞는 장기 보관 | — |
| `assets/` | 이미지·PDF·첨부 (아래 규칙) | 스크린샷, 차트 이미지 |

**번호는 10 단위로 띄워 두었습니다.** 새 카테고리가 필요하면 사이에 끼워 넣으세요 (`25-`, `45-` …).
기존 번호를 바꾸면 `wiki/sources/` 매핑이 깨지므로 **재번호는 하지 않습니다.**

## 파일 이름 규칙

```
<발행일 YYYY-MM-DD>_<발행처>_<제목-슬러그>.<확장자>
예) 2025-10-20_윤선생_초등학부모-용돈설문.md
    2024-10-09_전자신문_퍼핀-가입자현황.md
```

발행일을 모르면 수집일을 쓰고 파일 안에 `수집일` 로 명시합니다.

## 첨부 파일 (`assets/`)

원본 문서 하나당 하위 폴더 하나:

```
raw/assets/<원본 파일명과 같은 슬러그>/image-01.png
```

Obsidian Web Clipper를 쓴다면 설정 → 파일 및 링크 → "첨부 파일 폴더 경로"를 `raw/assets/` 로 지정하세요.

## 확장 규칙 (원본 500~2,000개 대비)

- **한 폴더가 150개를 넘으면 하위 분할합니다.** 분할 축은 두 가지 중 하나만 고릅니다 —
  **연도**(`30-research/2025/`) 또는 **세부 주제**(`20-services/국내/`, `20-services/해외/`).
  한 폴더 안에서 두 축을 섞지 않습니다.
- **깊이는 3단계까지** (`raw/20-services/국내/파일.md`). 그보다 깊어지면 카테고리를 새로 파는 게 맞습니다.
- 분할했으면 `wiki/sources/` 의 같은 번호 폴더도 **똑같이** 분할합니다.
