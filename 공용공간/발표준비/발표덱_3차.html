기술 ①

배운 걸 실제로 했는지 증명하기

아이가 퀴즈를 풀어 별을 받는 순간, 서버는 그 정답과 같은 주제의 실천 미션을 곧바로 연결해 보여줍니다. 미션을 사진으로 인증하면 부모에게 승인 요청이 가고, 부모가 승인하면 별이 지급됩니다. 72시간 안에 부모 확인이 없으면 자동으로 지급되어, 아이가 한 일이 부모 사정으로 사라지지 않습니다(ADR-016).

쓰는 기술
서버(Next.js 서버 런타임)가 학습 이벤트와 미션 이벤트를 하나의 흐름으로 묶고, 이 지급을 원장(PostgreSQL) 이중 기입으로 기록
보여주는 방식
“퀴즈 정답 → 별 1개 → 실천 카드 등장 → 사진 인증 → 부모 승인 → 별 확정 → 나무 성장”이 화면 안에서 끊기지 않고 이어짐. 승인용 사진은 확인 즉시 서버에서 삭제되어, 화면에는 “승인됨” 표시만 남음

기술 ②

부모와 아이 화면 분리하기

부모 앱과 아이 앱은 겉보기엔 한 서비스지만, 실제로는 서로 다른 주소(오리진)로 배포된 별개의 PWA입니다.

쓰는 기술
PWA 2개(부모/아이) + 오리진 분리, 아이 토큰으로는 부모 API를 아예 호출할 수 없게 서버가 막음
보여주는 방식
부모는 초대 링크를 만들어 문자로 보내고, 아이는 그 링크로만 들어옴. 두 화면이 같은 코드베이스(Next.js)에서 나오지만, 사용자는 완전히 분리된 두 개의 앱처럼 경험함

기술 ③

인터넷이 끊겨도 성장 기록 지키기

아이가 오프라인 상태에서 미션을 완료해도 기록이 사라지지 않습니다.

쓰는 기술
아이 앱의 Service Worker가 오프라인 큐에 행동을 잠깐 저장해두고, 재연결되면 고유 키(멱등 키)로 서버에 전송해 중복 지급을 막음
보여주는 방식
화면엔 “오프라인” 표시만 뜨고, 다시 연결되면 자동으로 별이 반영됨 — 아이가 따로 뭘 다시 누를 필요가 없음

기술 ④

이번 달 얼마나 자랐는지 말로 설명하기

숫자(별 개수·완료 미션 수)만 보여주는 대신, 한 줄 요약 문장으로 성장을 설명합니다.

쓰는 기술
AWS Bedrock(Claude, 서울 리전)을 이 기능 하나에만 사용. 아동 식별 정보 없이 집계 수치만 넘김
보여주는 방식
월간 숲 화면 상단에 “이번 달엔 저축을 3번 더 실천했어요” 같은 한 줄이 뜸. 기능이 꺼져 있어도 숫자·그래프 지표는 그대로 보이므로, AI는 있으면 좋은 설명이지 서비스의 전제가 아님
