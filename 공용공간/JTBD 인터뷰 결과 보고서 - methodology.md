## 1️⃣ JTBD 인터뷰 실행에서 얻을 수 있는 결과의 목록

| 필드 | 작성 가이드 |
| --- | --- |
| **Persona / Segment** | 코어·확장·극단·비활성 중 분류 + 짧은 설명(직무/맥락) |
| **Situation (When …)** | 전환을 유발한 "상황적 맥락" 한 문장 |
| **Job Statement (… I want to …)** | 사용자가 "해결하려는 핵심 일(진보)" 한 문장 |
| **Desired Outcome (… so I can …)** | **달성하고 싶은 결과(측정 가능 표현)** |
| **4 Forces** | Push(현상 불만), Pull(새 솔루션 매력), Habit(관성), Anxiety(불안) 각 1–2줄 |
| **Current Solutions / Workarounds** | 현재 쓰는 대체수단(툴/사람/엑셀/수기 등) |
| **Switch Triggers / Barriers** | 채택/이탈을 유발한 계기와 장애요인 |
| **Evidence (Quotes / Data)** | 인터뷰 인용 1–2개 + 로그/지표/리뷰 근거 |
| **Priority (AOS / DOS)** | AOS = Imp × (1 − Sat/5), DOS = (Imp − Sat) × TAM(%) |
| **Notes** | 실험 아이디어, 리스크, 추정 가설 |

## 2️⃣ `JTBD 요약 카드` 작성 예시

> **"실질적인 잠재고객 인터뷰"를 수행한 후** 아래와 같은 항목 구성으로 핵심 인사이트를 요약합니다.
> *(아래는 극단적으로 짧은 예시임)*

| 구분 | 내용 |
| --- | --- |
| **Persona / Segment** | **코어** – 초기 단계 **`B2B SaaS 비즈니스`의 운영 매니저** (5~20명 조직) |
| **Situation** | **월말 경영회의를 48시간 앞둔 상황** |
| **Job Statement** | **지표를 한 번에 모아 경영진용 리포트를 신뢰성 있게 제출하고자 함** |
| **Desired Outcome** | **에러 0건, 취합 시간 4시간 → 30분 단축, 승인 1회 통과** |
| **4 Forces** | **Push:** 수작업 취합 스트레스<br>**Pull:** 자동 수집·요약에 대한 기대<br>**Habit:** 익숙한 스프레드시트 중심 업무 패턴<br>**Anxiety:** 새 툴 도입 시 권한/보안 이슈 |
| **Current Solutions** | **Google Sheet + 수동 CSV 업로드 + Slack 요청** |
| **Switch Triggers / Barriers** | **Trigger:** CFO의 "오탈자 지적" 이후 자동화 도구 탐색 시작<br>**Barrier:** 보안·권한 관리 이슈로 도입 보류 |
| **Evidence (근거)** | "전표가 늦게 들어와 엑셀을 다시 합쳐요."<br>지난 3개월 평균 취합시간 **5.6시간** |
| **Priority (AOS / DOS)** | **AOS = 3.0**, **DOS = 2.4** (Importance=5, Satisfaction=2, TAM=0.8) |
| **Notes (추가 메모)** | **MVP:** 3소스 연결, 자동 요약, PDF 내보내기 기능 중심<br>SSO 통합 필수 |

# 📌 본 프로젝트 적용 기준

> 여기서부터는 위 프레임을 **핀프렌즈에 적용할 때의 규칙**입니다. 위 1️⃣~3️⃣은 원 방법론이고, 아래는 우리 프로젝트의 결정 사항입니다.

## 📎 필드별로 어느 문서에서 가져오는가

| 필드 | 가져올 곳 | 주의 |
|---|---|---|
| **Persona / Segment** | 스펙트럼 v2 §2-2 — Core·Adjacent·Extreme·Non-user + 시장 세그먼트 ①~④ | **두 축이 다릅니다.** 어느 축인지 반드시 표기 |
| **Situation** | 여정지도 최종 §3~6의 **1단계(문제 신호)** 행 | *"When ~"* 한 문장으로 압축 |
| **Job Statement** | 페인포인트 차트 §1의 **페르소나 Goal** | 그대로 쓰지 말고 *"I want to ~"* 형태로 재작성 |
| **Desired Outcome** | 페인포인트 차트의 **Pain별 Goal** + 여정지도 §10-2 KPI | 🔴 **측정 가능한 표현으로 바꿔야 함** (아래 참조) |
| **4 Forces** | Push·Habit → 스펙트럼 v2 카드 / Pull·Anxiety → 인터뷰 Part 2·4 | Anxiety는 **Q4-2·Q4-3** 답에서 뽑음 |
| **Current Solutions** | 인터뷰 문항지 §1-1의 「현재 대체 솔루션」 표 · Part 0 응답 | |
| **Switch Triggers / Barriers** | 여정지도 §7-2 이탈 유형 표 · 인터뷰 Q4-1·Q4-2 | |
| **Evidence** | 인터뷰 녹취 인용 + 시장분석/리뷰분석 지표 | 🔴 **모의 응답은 Evidence가 될 수 없음** (아래 참조) |
| **Priority (AOS / DOS)** | AOS·DOS 분석 §3·§6·§7 값을 **그대로** 인용 | 재계산하지 말고 ID(C1~C12·A1~A6)로 참조 |
| **Notes** | v13 §13 검증과제 · §14 남은 설계 질문과 연결 | |

## ⚠️ 필드 가이드의 「TAM(%)」는 우리 프로젝트에서 **TAM이 아닙니다**

1️⃣의 DOS 수식은 `DOS = (Imp − Sat) × TAM(%)`으로 적혀 있지만, [`AOS, DOS - methodology.md`](AOS,%20DOS%20-%20methodology.md) 4️⃣의 정확한 정의는 **`× Market Relevance`**이고 그 값은 *"TAM-SAM-SOM 중 **적정 모수**에 대한 해당 Pain/Goal의 비중"*입니다.

[`기회점수_AOS_DOS_분석.md`](기회점수_AOS_DOS_분석.md) §5-1에서 **모수를 이미 확정했습니다.**

| 모수 | 값 | 용도 |
|---|---|---|
| ❌ TAM | 2.6조원 (글로벌 금액) | **쓰지 않음** — 단위 불일치 · 변별력 소실 |
| ✅ **SAM 대용** | **817,830명** (초등 1~3 용돈 지급 가정) | 로드맵·확장 판단 |
| ✅ **SOM** | **293,149명** (① 금융성장 증명형) | MVP 범위 결정 |
| ❌ SOM Level 3 | 440가구 | **쓰지 않음** — 구독 전제이나 v13에서 무료 확정 |

> **카드의 Priority 필드에는 「TAM(%)」 대신 `DOS(SAM) / DOS(SOM)` 두 값을 병기**합니다. 하나만 적으면 §8-2에서 확인한 **AOS 1위가 DOS 9위로 내려가는 괴리**가 카드에서 사라집니다.

## 🔴 Evidence 필드 — 지금은 채울 수 없습니다

1️⃣의 전제는 *"실질적인 잠재고객 인터뷰를 **수행한 후**"*입니다. **현재 부모 인터뷰 0건 · 아이 인터뷰 0건**입니다.

[`인터뷰_문항지_및_모의응답.md`](인터뷰_문항지_및_모의응답.md) 5·6부의 응답은 **문항을 검사하려고 만든 [합성 가설]**이며, 그 문서 §8이 인용을 금지하고 있습니다.

| 상태 | Evidence 필드에 무엇을 쓰는가 |
|---|---|
| **인터뷰 전 (현재)** | 🔴 인용문 자리에 **`⬜ 미수집`**으로 두고, **관측 지표만** 채운다 (리뷰 921건 · 퍼핀 공시 · 시장 통계) |
| **인터뷰 후** | 녹취 인용 1–2개 + 관측 지표. **모의 응답은 삭제하지 말고 나란히 두어 어디서 빗나갔는지 남긴다** |

> **인터뷰 전에 카드를 쓰는 것 자체는 유효합니다** — 다만 그때의 카드는 *결과 보고서*가 아니라 **인터뷰에서 확인할 가설 카드**이며, 문서 제목과 각 카드에 그 사실을 명시합니다.

## 🎯 카드를 몇 장 쓰는가

| 대상 | 카드 | 근거 |
|---|:-:|---|
| **H1 정미경형** (Core / ① 성장증명형) | **1장** | 1차 인터뷰 확정 · DOS SAM·SOM 양쪽 1위 |
| **H6 임태경형** (Adjacent / ③ 소비통제형) | **1장** | 1차 인터뷰 확정 · **AOS 1위 ↔ DOS 9위** 괴리 판정용 |
| H2·H3·H4·H5 | 2차 라운드 | 스펙트럼 v2 §3-3 모집 8슬롯 중 나머지 |
| Extreme·Non-user | 별도 프레임 | AOS·DOS 분석에서 제외된 유형 (§0-1) |

## ✅ Desired Outcome은 반드시 측정 가능해야 합니다

예시 카드의 *"취합 시간 4시간 → 30분, 에러 0건, 승인 1회 통과"*가 기준선입니다. 우리 페인포인트 차트의 Goal은 **아직 정성 문장**이므로 카드에 옮길 때 수치화합니다.

| 차트의 Goal (정성) | → | 카드의 Desired Outcome (측정 가능) |
|---|:-:|---|
| *"활동량이 아니라 변화를 읽고 싶다"* | → | 확인 시간 **주 15분 → 3분** · 나무 근거 열람률 · *"이번 달 무엇이 달라졌나"* **1문장 회상 성공** |
| *"얼마 줄었다는 숫자 하나를 보고 싶다"* | → | 월간 숲 첫 화면에 **전월 대비 지출 증감액 노출** · 1개월 후 연결 유지 |

> 수치 출처는 [`고객여정지도_최종.md`](고객여정지도_최종.md) §10-2 KPI 표를 씁니다. **없는 수치를 지어내지 않고, 없으면 `⬜ 기준선 미측정`으로 둡니다.**

## 📝 작성 순서

```
① 카드 골격 채우기        Persona → Situation → Job → Desired Outcome
        ↓                 (스펙트럼 v2 · 여정지도 · 페인포인트 차트에서 인용)
② 4 Forces 4칸            Push·Habit는 기존 문서 / Pull·Anxiety는 인터뷰 응답
        ↓
③ Priority 붙이기         AOS·DOS 분석의 ID를 그대로 참조 (재계산 금지)
        ↓
④ Evidence 채우기         인터뷰 전에는 ⬜ 미수집 + 관측 지표만
        ↓
⑤ Outcome 목록 표         카드 전체를 가로질러 Outcome 단위로 다시 정렬
        ↓
⑥ Notes                   v13 §13 검증과제 · §14 설계 질문으로 연결
```

## 🚫 사용 금지선

- **카드의 Job Statement를 「우리가 만들고 싶은 기능」으로 쓰지 않습니다.** Job은 고객이 이루려는 진보이지 솔루션이 아닙니다. *"성장 나무를 보고 싶다"* ✗ → *"배운 것이 행동으로 이어졌는지 확인하고 싶다"* ✓
- **AOS·DOS를 카드에서 다시 계산하지 않습니다.** 값이 두 문서에서 갈리면 추적이 불가능해집니다. **ID로 참조**합니다.
- **인터뷰 전 카드는 「가설 카드」로 명시**하고, 발표·PRD에 *결과*로 인용하지 않습니다.
- **4 Forces 중 Anxiety를 비워두지 않습니다.** 비어 있으면 *"불안이 없다"*가 아니라 **아직 안 물어본 것**이며, 그 자체를 다음 인터뷰 항목으로 올립니다.
