## 한눈에 보는 대응표

|:-:|---|---|---|
| ✅ | 배운 것을 실천으로 옮기는 루프 | 서버(Next.js 16 Server Action)가 퀴즈 정답과 미션 승인을 하나의 흐름으로 묶어 처리 | 정답 → 별 지급 → 바로 이어지는 "실천하기" 카드 |
| ✅ | 미션이 부모 사정으로 사라지지 않음 | 72시간 무응답이면 서버가 자동 지급(`ADR-016`) | 아이 화면에 「승인 대기」가 떠 있다가 스스로 확정됨 |
| ✅ | 미션 사진은 남기지 않음 | 사진을 원장이 아닌 별도 표에 두고, 보호자 판정 직후 즉시 파기 | 사진은 "칭찬하기"를 누르는 순간까지만 보이고, 이후엔 승인 배지만 남음 |
| ✅ | 별이 사라지거나 두 번 지급되지 않음 | 잔액을 저장하지 않고 **원장 합**으로 계산 + `idempotency_key` unique 제약 | 부모·아이 화면의 별 개수가 **항상 일치** |
| ✅ | 어긋난 기록이 아이를 벌하지 않음 | 정합성 정산이 어긋난 줄에 **격리 표시만** 하고 잔액은 건드리지 않음(`AC-012-3`) | 아이 별은 그대로, 보호자 화면에 「확인이 필요한 기록」으로 뜸 |
| ✅ | 아이가 계속 오게 만드는 보상 | three.js 3D 아바타·방, 에셋 전부 CC0 | 상점에서 별로 사고 방에서 끌어 옮김. 별은 앱 안에서만 쓰임(`P-21`) |
| ✅ | 아이 화면에 부모 기능이 섞이지 않음 | 미들웨어 · 서버 함수 인가 · 아이 번들 빌드 게이트 **세 겹** | 아이 기기에서 부모 주소를 직접 쳐도 열리지 않음 |
| ✅ | 아이에게 검수 안 된 글을 보여주지 않음 | 학습 지문·퀴즈를 **코드에 고정**하고 사람이 검수 | 아이 화면에 실시간 생성 텍스트가 없고, 이미 만들어진 이야기·퀴즈만 나타남 |
| ⬜ | 부모/아이 화면 완전 분리 | PWA 2개를 **다른 오리진**으로 배포 | 부모는 부모 링크, 아이는 아이 링크로만 들어감 |
| ⬜ | 월간 성장 요약 | AI(AWS Bedrock, 서울 리전)를 **부모용 요약 문장 하나**에만 사용 | 월간 숲 화면에 "이번 달엔 저축을 3번 더 실천했어요" 같은 한 줄 |
| ⬜ | 아동 정보가 해외로 나가지 않음 | 전체 인프라를 국내 리전에 고정 | 개인정보 처리방침에 "국내 서버"로 명시 |
| 🔁 | 인터넷이 끊겨도 별이 안전함 | 아이 앱에 Service Worker 오프라인 큐 | — **기각.** 아래 §3 |

## 이야기로 풀면

### 1. ✅ "배운 걸 실제로 했는지"를 증명하는 기술

아이가 퀴즈를 풀어 별을 받는 순간, 서버는 그 정답과 **같은 주제의 실천 미션**을 곧바로 연결해 보여줍니다. 미션을 사진으로 인증하면 부모에게 승인 요청이 가고, 부모가 승인하면 별이 지급됩니다. **72시간 안에 부모 확인이 없으면 자동으로 지급**되어, 아이가 한 일이 부모 사정으로 사라지지 않습니다(`ADR-016`).

- **쓰는 기술**: 서버(Next.js 16 Server Action)가 학습 이벤트와 미션 이벤트를 하나의 흐름으로 묶고, 지급을 **PostgreSQL 원장**에 남김.
- **보여주는 방식**: "퀴즈 정답 → 별 1개 → 실천 카드 등장 → 사진 인증 → 부모 승인 → 별 확정 → 나무 성장"이 화면 안에서 끊기지 않고 이어짐. 승인용으로 받은 사진은 판정 즉시 서버에서 삭제되어, 화면에는 "승인됨" 표시만 남습니다. **판정이 끝난 미션의 사진 주소는 404** 입니다 — 오류가 아니라 「지워졌다」는 뜻입니다.

### 2. ✅ 아이 화면에 부모 기능이 섞이지 않게 하는 기술

화면에서 링크를 지우는 것으로는 부족합니다 — **주소를 직접 치면 열립니다.** 아이가 자기 미션을 스스로 승인할 수 있으면 보호자 승인이라는 절차가 무의미해지므로(`PRC-001`), 세 겹으로 막습니다.

- **쓰는 기술**
  1. **미들웨어** — 아이 기기로 표시된 브라우저가 부모 화면 주소로 들어오면 서버가 그 자리에서 돌려보냄. 쿠키는 지울 수 있으므로 1차 관문으로만 취급.
  2. **서버 함수 인가** — 보호자 화면의 모든 Server Action이 각자 첫 줄에서 인가를 다시 확인. 미션 사진 경로도 미션 id만으로는 열리지 않고 보호자 id를 함께 걸어 조회.
  3. **빌드 게이트** — 아이 화면이 부모 전용 모듈을 import 했는지, 빌드 산출물의 아이 번들에 부모 경로 문자열이 남았는지 검사해 하나라도 걸리면 빌드를 세움(`npm run gate:origin`).
- **보여주는 방식**: 부모는 1회용 초대 코드를 만들어 아이 기기를 등록하고, 아이 기기는 아이 화면에만 머무릅니다.
- ⚠️ **오리진 분리는 아닙니다.** 단일 Next 앱이라 도메인을 가르지 못합니다(`CON-01`). `AC-003-2`가 요구하는 「아이 번들에 부모 엔드포인트 문자열 0건」을 **빌드 게이트로** 검증합니다 — 어긋남 대장 `D38`. 오리진 2개 분리는 아래 §5에 미구현으로 남아 있습니다.

### 3. 🔁 오프라인 큐 — 기각하고 서버 멱등 키로 대체

**Service Worker는 요청을 가로채지 않습니다.** 캐싱도 하지 않고, 웹 푸시 수신만 합니다(어긋남 대장 `D56`).

- **기각 사유**: 이 앱은 잔액·미션 상태처럼 **낡으면 안 되는 숫자**를 보여줍니다. 워커가 오래된 화면을 돌려주면 **부모와 아이가 다른 잔액을 봅니다.**
- **대신 무엇이 요구를 지키는가**: *"오프라인 후 ⭐ 중복 지급 0건"* 은 **서버 원장의 `idempotency_key` unique 제약**이 보증합니다. 같은 요청이 두 번 들어와도 두 번째가 DB에 들어가지 못합니다 — 애플리케이션 판단에 맡기지 않습니다.
- **되돌리는 조건**: 오프라인 체류가 실제 이탈 사유로 관측되면, **읽기 캐시 없이 쓰기 큐만** 두는 형태로 다시 검토합니다.

### 4. ✅ 별이 사라지거나 두 번 지급되지 않는 기술

**잔액을 따로 저장하지 않습니다.** 원장에 쌓인 증감의 합이 곧 잔액입니다 — 둘을 따로 두면 어긋나는 순간 어느 쪽이 맞는지 알 수 없습니다(`REQ-NF-006` 오류율 0%).

- **쓰는 기술**: PostgreSQL **append-only 원장** + 멱등 키 unique 제약 + 정합성 정산(`reconcileStars`).
- **보여주는 방식**: 부모·아이 화면의 별 개수가 항상 일치합니다. 합이 어긋난 줄은 **격리 표시만** 하고 아이 잔액은 건드리지 않습니다(`AC-012-3`) — 아이가 잘못한 게 아닌데 어제 본 별이 오늘 줄면 그 화면을 다시는 믿지 못합니다. 늦게 승인된 지난달 실천이 들어오면 그 달 월말 기록을 **다시 계산해 덮어씁니다.**
- ⚠️ **실행 시점이 배치가 아닙니다.** 주기 전환·월말 스냅샷·원장 정산 세 함수를 **나무·숲 화면을 열 때** 부릅니다(`D39`). 아무도 화면을 안 열면 돌지 않으므로, 운영에는 cron 연결이 남아 있습니다.

### 5. ⬜ 부모와 아이를 오리진으로 가르는 기술 *(미구현)*

부모 앱과 아이 앱을 **서로 다른 주소(오리진)**로 배포된 별개의 PWA로 만드는 계획입니다(`ADR-005` · `P-05`).

- **지금은**: 단일 앱·단일 오리진이고, PWA 매니페스트도 하나입니다. 시작 주소가 기기를 보고 아이·보호자 화면으로 가릅니다.
- **같은 요구를 지금 무엇이 지키는가**: §2의 세 겹.
- **남은 일**: 도메인을 가르고, 아이 오리진 번들 정적 스캔을 배포 차단 게이트로 승격.

### 6. ⬜ "이번 달 얼마나 자랐는지"를 말로 설명하는 기술 *(미구현)*

숫자(별 개수·완료 미션 수)만 보여주는 대신, 한 줄 요약 문장으로 성장을 설명하는 계획입니다(`FR-042`).

- **지금은**: 월간 숲이 **획득 별과 전월 대비 변화**까지 보여주고, **AI 요약 문장은 붙어 있지 않습니다.** 데모에는 런타임 AI 호출이 한 건도 없습니다.
- **쓸 기술**: AWS Bedrock(Claude, 서울 리전)을 **이 기능 하나에만** 사용. 아동 식별 정보 없이 집계 수치만 넘김.
- **왜 미루어도 괜찮은가**: 이 기능이 꺼져 있어도 숫자·그래프 지표는 그대로 보이므로, AI는 **있으면 좋은 설명**이지 서비스의 전제가 아닙니다. 엔드포인트를 하나로 분리해 둔 이유가 이것입니다 — **끄는 일이 엔드포인트 하나를 내리는 일**이 됩니다.

### 7. ✅ 아이에게는 미리 검수된 내용만 보여주는 기술

학습 지문·퀴즈는 아이가 보기 전에 이미 사람이 확인을 끝낸 콘텐츠입니다.

- **쓰는 기술**: 지문·퀴즈를 **코드에 고정**하고(회원 데이터가 아니라 글이므로 DB에 두지 않습니다), DB는 **누가 무엇을 읽었는가**만 압니다. 개념과 오개념은 금융감독원 「초등학교 3·4학년 금융생활 익힘책」 등에서 가져오되 원문을 옮기지 않았습니다.
- **보여주는 방식**: 아이 화면에는 실시간으로 생성되는 글이 없고, 이미 완성되어 배포된 이야기와 퀴즈만 나타납니다. 오답이어도 그 자리에서 AI가 설명을 새로 만들어주는 게 아니라, 정해진 "이야기 다시 읽기"로 안내합니다.
- ⚠️ **저작 도구(Python·FastAPI·ChromaDB)는 아직 없습니다.** 지금은 사람이 직접 씁니다. 콘텐츠가 16편을 넘어 중복·난이도 드리프트 검사가 필요해지는 시점에 만듭니다.

### 8. ✅ 여덟 살이 계속 오게 만드는 기술

모은 별로 아이템을 사서 아바타와 방을 꾸밉니다. 여덟 살에게는 나무·진도율보다 이 변화가 훨씬 잘 통합니다 — 같은 기록이 보호자 화면에서는 나무로 번역됩니다.

- **쓰는 기술**: **three.js**를 아이 화면에서만 지연 로드. 캐릭터 12종 · 펫 11종 · 7개 분류 71개 아이템, 에셋은 전부 **CC0**라 3D 제작비가 들지 않습니다.
- **보여주는 방식**: 상점에서 별로 사고, 방에서 끌어 옮기고 돌립니다. 별은 **앱 안 아이템으로만** 바뀝니다 — 현금·현물·제휴처 경로를 만들지 않았습니다(`P-21`). 얼굴을 수집하지 않고 생성형 AI를 쓰지 않습니다(`P-13`).
- ⚠️ **UI 의존성 0건 규칙의 예외입니다.** `REQ-TEC-007`이 Tailwind + shadcn/ui 외 의존성 0건을 요구하고 `ADR-T05`가 Lottie 2.5D를 지정했는데, 3D로 갔습니다 — 어긋남 대장 `D2`·`D3`. **승인이 남아 있습니다.**

## 정리 — 스택은 취향이 아니라 약속의 결과

기술 선택 모두 같은 원칙을 따릅니다: **먼저 지켜야 할 약속(성장 증거를 보여준다·아동 정보를 보호한다·AI는 보조일 뿐이다)이 있고, 기술은 그 약속을 지키기 위해 역산해서 고른 것**입니다.

그래서 **약속이 지켜지면 기술은 바뀔 수 있습니다.** §2의 세 겹은 오리진 분리가 아니지만 같은 요구를 지키고, §3은 오프라인 큐를 버렸지만 「중복 지급 0건」은 서버 원장이 지킵니다. 발표에서는 **약속을 먼저 말하고 기술을 뒤에** 두는 편이 안전합니다 — 기술 이름을 먼저 걸면 없는 것을 말하게 됩니다.

전체 스택 목록과 각 항목의 규제 근거는 `SRS_핀프렌즈_v1_0.md` §2.5, `wiki/10-제품/기술-스택.md`에 정리돼 있습니다.
