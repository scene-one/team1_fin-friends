# 기술기획 산출물

새싹프렌즈 1팀 · 2차 역기획 프로젝트 · **수빈** 작성 / **병윤** 구현 · 2026-09-01

> 기술기획을 **두 관점**으로 나눠 담았습니다.

| 관점 | 무엇을 다루나 |
|---|---|
| 🅰️ **비즈니스 로직** | 서비스의 **핵심 시나리오**를 소프트웨어의 **기능과 성능**으로 표현. 이야기로 공유하기 위해 **시퀀스 다이어그램의 증강 형태**로 정리 |
| 🅱️ **딜리버리 로직** | 사용자의 **화면에 도달**하기 위한 기술적 방법. 사용 기술 스택에 따른 **FE–BE 구조와 배포 전략** |

## 🅰️ [비즈니스 로직](비즈니스%20로직/)

| 문서 | 내용 |
|---|---|
| [**증강 시퀀스 다이어그램 (구현 명세)**](비즈니스%20로직/증강%20시퀀스%20다이어그램%20(구현%20명세).md) | 시퀀스 **6개**(SRS §3의 4개 증강 + 신규 2개). 화살표마다 **성능 상한 · 예외 분기 · 규제 게이트 · 이벤트 적재 · 멱등 키** 병기 |
| [**API 명세 (계약 수준)**](비즈니스%20로직/API%20명세%20(계약%20수준).md) | 엔드포인트 **38개**(부모 17 · 아이 10 · 외부 2 · 배치 9). 위 시퀀스의 화살표에서 그대로 뽑았습니다 |

**왜 API 명세가 여기 있나** — 스택과 무관하게 성립하는 **계약 수준**이고, 각 엔드포인트가 담는 것이 *"무엇을 주고받고 얼마나 빨라야 하는가"* 이기 때문입니다. **인증 구현·프레임워크·스키마 타입은 다루지 않습니다**(그건 🅱️와 병윤 님 재량).

## 🅱️ [딜리버리 로직](딜리버리%20로직/)

| 문서 | 내용 |
|---|---|
| [**시스템 아키텍처 · 배포 설계 (기획 관점)**](딜리버리%20로직/시스템%20아키텍처%20·%20배포%20설계%20(기획%20관점).md) | **아키텍처**(신뢰 경계 3겹 · 계층 · 어댑터) + **배포·환경**(환경 3종 · 배포 관문 4개 · 게이트 승격 · 롤백) |

**둘을 한 문서로 묶은 이유** — 배포 전략이 아키텍처 결정에서 곧바로 파생됩니다. 예를 들어 *「모의 ↔ 운영을 빌드 타임에 분리한다」* 는 배포 결정인데, 그 근거는 **발행사를 어댑터로 끊은 아키텍처 결정**입니다.

---

## 🔑 만든 순서 — 이유가 있습니다

```
① 증강 시퀀스  →  ③ API 명세  →  ②④ 아키텍처 · 배포
```

**시퀀스를 먼저 그리면 거기 나온 화살표가 그대로 API 목록이 됩니다.** API를 먼저 설계하면 **시나리오에 없는 엔드포인트**를 만들게 됩니다.

> 실제로 API 명세를 쓰면서 엔드포인트가 **35 → 38**로 늘었는데, 새로 만든 게 아니라 **시퀀스에 있던 화살표를 놓쳤던 것**이었습니다.

## ⬜ 병윤 님이 정할 것

| 어디 | 무엇 |
|---|---|
| 시퀀스 §9 | **미확정 4건** — 미션 사진 보관 · 이자 지급 주체 · 주말 트리거 · 환불·파기 순서 |
| API 명세 §6 | 위 4건이 걸리는 **갈림길 3곳**. 나머지 엔드포인트는 **확정**이고, 정해지는 대로 §6만 갈아끼우면 됩니다 |
| API 명세 §8 | 인증 구현 · 에러 코드 · 페이지네이션 · 어댑터 인터페이스 |
| 아키텍처 §8 | 호스팅 · DB · CI · Service Worker 캐시 전략 · 관측 스택 |

🔴 **가장 먼저 닫아야 할 것은 시퀀스 §9-1(미션 사진 보관)** 입니다. **스토리지와 스키마를 바꾸므로** 뒤에 정하면 엔드포인트 시그니처까지 다시 써야 합니다.

## 📌 물러설 수 없는 것

구현 방식은 자유지만, 이 항목들은 **규제와 제품 결정에서 역산된 계약**입니다.

**API** *(명세 §8)* — 스코프 2종·403 강제 · 규제 게이트는 HTTP 상태로 거부 · 별이 움직이는 쓰기는 전부 멱등 · ⭐ 판정 스냅샷 고정 · 금지 컬럼 부재 · 주차 귀속은 `client_ts`

**아키텍처** *(아키텍처 §8)* — 오리진 2개 분리 · 결제 원본 미보관 · 별 원장 append-only + 일일 대사 · 모의↔운영 빌드 타임 분리 · 제3자 오리진 요청 0건
