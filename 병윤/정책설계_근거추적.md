## 0. 내 산출물이 뭔지

| | |
|---|---|
| ❌ **아님** | 퍼핀 약관·도움말을 수집해서 정리하기 |
| ⭕ **이것** | **핀프렌즈**의 약관·도움말을 설계하고, **각 조항이 왜 그렇게 쓰였는지** 근거를 추적 가능하게 만들기 |

퍼핀 문서 수집은 **재료**입니다. 목적은 「퍼핀은 이 법적 의무를 어떤 조항으로 처리했나」를 역산해서, 우리는 같이 갈지 다르게 갈지 결정하는 것.

## 1. 왜 이게 배점인가

가이드 평가 기준에 직접 걸립니다.

| 평가 항목 | 배점 | 관련 문구 |
|---|---|---|
| Value Proposition과 PRD | **15** | "모든 Must 요구사항이 고객 가치 또는 **필수 도메인 제약**으로 추적되는가" |
| 실행 가능성과 도메인 책임 | **10** | "필요 데이터·**정책**·상태·예외와 산업별 법·윤리·운영 위험" |
| 근거와 추론의 투명성 | **10** | "출처가 추적되며 Fact·Inference·Assumption과 검증과제가 구분됨" |

그리고 운영 원칙 5:
> 「도메인별 제약을 **마지막 체크리스트가 아니라 설계 입력값**으로 다룬다」

**약관을 뒤에 첨부하면 0점, 요구사항으로 추적되면 점수입니다.**

## 2. 🔥 핵심 발견 — 퍼핀 불만의 상당수가 「정책·고지의 실패」다

1차에서 모은 퍼핀 리뷰를 다시 보면, UI 문제가 아니라 **약관·동의·도움말이 제대로 설계되지 않아서 생긴 불만**이 큰 축을 이룹니다.

| 퍼핀 리뷰 (1차 수집) | 실제 원인 | 핀프렌즈에서 정책으로 해결 |
|---|---|---|
| "9만원 결제 했는데 퀴즈 하루에 3개밖에 못품. 기사 보려면 또 따로 결제해야함. **왜 결제 하는지 이유를 모르겠슴**" | 구독 **혜택 범위 고지 불충분** (금융소비자보호법 설명의무 영역) | 결제 전 화면에 포함/미포함 항목 명시 + 도움말에 비교표 |
| "제발 이상한 광고 알림 보내지 마세요!!!!! 계속 퍼핀플러스 가입하라고 생쇼를 다하는데" | **마케팅 수신 동의가 서비스 동의와 분리되지 않음** | 마케팅 동의 별도 분리 + 아이 화면 광고 금지를 약관에 명문화 |
| "광고를 통해 용돈 관리력을 기르기 전에 **현질에 노출**될 가능성이 크다… 광고 알림 눌러서 계좌번호 누르라고 해서 눌렸다는 우리 아들" | 아동 화면 **광고 정책 부재** | "아동 화면에 결제 유도 광고를 노출하지 않는다"를 정책 요구사항으로 |
| "카드 안만들면 아예 앱을 둘러볼수가없네요.. **어떤수준으로 교육이 되는지 볼려했는데**" | **사전 안내·도움말 부재** | 가입 전 커리큘럼 공개 (도움말이 곧 기능) |
| "한문제가 쓰레기 아니면 발자국이였는데 **두개다 틀렸다고 해요** 고쳐주세요" | **콘텐츠 오류 정정 절차 없음** | 오류 신고·정정·재채점 절차를 약관에 규정 |

### 그래서 이 프로젝트에서의 주장

> **"약관과 도움말은 법률 방어 문서가 아니라 제품이다."**
> 퍼핀은 여기서 실패해서 별 1점을 받고 있다. 우리는 이걸 설계 입력값으로 다룬다.

이 한 문장이 내 파트의 발표 메시지입니다.

## 3. 작업 순서 5단계

### Step 1. 퍼핀 문서 **역산** (수집이 아니라 역산)

읽으면서 이 질문에 답합니다.

| 읽을 문서 | 답할 질문 |
|---|---|
| 이용약관 | 퍼핀은 어떤 권리·의무를 스스로 규정했나? 면책 범위는? |
| 개인정보처리방침 | **수집 항목 · 보유기간 · 제3자 제공 · 만 14세 미만 처리**를 어떻게 적었나? |
| 전자금융거래 약관 | 카드·잔액을 어떤 법적 성격으로 규정했나? (선불? 여신?) |
| 도움말/FAQ | 약관에 없는 **실제 운영 규칙**이 뭐가 있나? |
| 퍼핀플러스 결제 화면 | 혜택 범위를 어디까지 고지했나? (리뷰 불만의 근원) |

> 📌 PDF·스크린샷으로 저장하고 **파일명에 날짜**를 넣으세요. 약관은 조용히 바뀝니다.
> `퍼핀_개인정보처리방침_20260818.pdf`

### Step 2. 법령에서 **최소선** 확인

Step 1에서 발견한 조항이 **법이 요구하는 최소인지, 퍼핀이 선택한 것인지** 가른다.
→ 법이 요구하는 것은 우리도 해야 함. 퍼핀이 선택한 것은 우리가 다르게 할 수 있음. **이 구분이 핵심.**

⚠️ 법령은 반드시 [국가법령정보센터](https://law.go.kr) 원문에서 확인 (§9 참고)

### Step 3. 1차 리뷰에서 「고지 실패로 생긴 불만」 추출

§2 표를 확장한다. 리뷰 원문 + 그게 어떤 정책의 부재인지.

### Step 4. 핀프렌즈 조항 작성 + **근거 추적표** (§4)

### Step 5. 하영에게 **요구사항 + 합격기준** 형태로 인계

정책을 문장으로 넘기면 PRD에 못 씁니다. §4 마지막 두 칸을 채워서 넘기세요.

## 4. ⭐ 정책 근거 추적표 — 핵심 산출물

**근거 엑셀 09_PRD 탭 또는 별도 탭에 이 형식으로.**

### 근거 유형 3분류

| 유형 | 뜻 | 판단 기준 |
|---|---|---|
| 🔴 **법적 의무** | 안 쓰면 위법 | 법령 원문에 근거가 있다 |
| 🟠 **리스크 방어** | 1차 규제 방어선을 약관에 명문화 | 별⭐/저금통🐷 구조를 지키기 위해 필요 |
| 🟢 **사용자 가치** | 퍼핀 페인포인트를 정책으로 해결 | 1차 리뷰 근거가 있다 ← **배점이 여기서 나옴** |

### 표 형식 + 작성 예시

| # | 핀프렌즈 조항 | 유형 | 근거 (출처·확인일) | 퍼핀은 어떻게 | 우리는 왜 이렇게 | PRD 요구사항 | 합격 기준 |
|---|---|---|---|---|---|---|---|
| P-01 | 별⭐은 현금·상품으로 **환급·양도·판매되지 않는다**. 서비스 종료 시에도 금전 보상 대상이 아니다 | 🟠 | 전자금융거래법 선불수단 정의 `조항 확인 필요` + 1차 결정(08/03) | 해당 재화 없음 (현금 직접 지급) | 선불업 등록·사행성 규제를 구조적으로 회피. 이 조항이 깨지면 사업 구조가 무너짐 | R-01 | 별→현금 전환 경로가 앱 내 **0개**임을 QA에서 확인 |
| P-02 | 저금통🐷 지급은 **부모 계정의 실제 이체로 이루어지며**, 회사는 목표·달성 기록만 관리한다 | 🟠 | 전자금융거래법 `확인 필요` + 1차 결정(기록형 저축) | 부모가 설정한 금액을 앱 내 잔액으로 지급 | 예치금을 보관하지 않아 선불업 등록 불필요 | R-02 | 회사 계좌를 경유하는 자금 흐름이 **없음**을 흐름도로 증명 |
| P-03 | 버닝퀴즈 오답 시 **보유한 별이 차감되지 않는다** | 🟠 | 사행행위규제법 `확인 필요` (재산상 손실 요건) | 해당 기능 없음 | "손실이 없으면 사행성이 아니다"를 약관에 박아 방어선을 명문화 | R-04 | 오답 시 별 잔액 변화량 = **0** |
| P-04 | 아바타 생성에 사용된 **원본 사진은 생성 직후 즉시 삭제**되며 서버에 저장되지 않는다 | 🔴🟠 | 개인정보 보호법(수집 최소화·파기) `조항 확인 필요` | 해당 기능 없음 | 아동 얼굴 이미지 보유 자체를 없애 최대 리스크를 제거 | R-07 | 생성 완료 후 원본 조회 시도 → **404** |
| P-05 | 만 14세 미만 아동의 가입·아바타 생성은 **법정대리인 동의 완료 후에만** 진행된다 | 🔴 | 개인정보 보호법 `조항 확인 필요` | (퍼핀 처리방침 확인 후 기입) | 주 사용자가 7~14세로 정면 해당 | R-03 | 동의 미완료 상태에서 생성 진입 **100% 차단** |
| P-06 | **마케팅 정보 수신 동의는 서비스 이용 동의와 분리**되며, 미동의 시 어떤 광고성 알림도 발송되지 않는다 | 🔴🟢 | 정보통신망법 `확인 필요` + **퍼핀 리뷰**("제발 광고 알림 보내지 마세요") | 통합 동의로 추정 → 아이 화면에 구독 유도 푸시 반복 | 퍼핀 최대 불만을 정책으로 직접 해결 | R-08 | 미동의 계정의 광고성 푸시 발송 **0건** |
| P-07 | **아동 화면에는 결제·구독을 유도하는 광고를 노출하지 않는다.** 결제 관련 안내는 부모 계정 화면에서만 제공한다 | 🟢🔴 | **퍼핀 리뷰**("현질에 노출", "광고 알림 눌러서 계좌번호") + 금융소비자보호법 광고규제 `확인 필요` | 아이 화면에 노출됨 (리뷰 다수) | 1차 결정(수익모델을 부모 구독으로 한정)의 약관 명문화 | R-09 | 아이 계정 화면의 결제 유도 컴포넌트 **0개** |
| P-08 | 구독 결제 화면에 **포함 항목과 미포함 항목을 함께 명시**한다 | 🟢🔴 | **퍼핀 리뷰**("9만원 결제했는데 퀴즈 하루 3개, 왜 결제하는지 모르겠슴") + 금융소비자보호법 설명의무 `확인 필요` | 혜택만 강조, 제한사항 고지 부족 | 구독 혜택을 **부모 인사이트**에 붙이는 1차 설계를 오해 없이 전달 | R-10 | 결제 전 화면에 미포함 항목이 **동일 위계로** 표시됨 |
| P-09 | 아이의 소비 내역 중 **부모에게 공유되는 범위를 아이가 확인할 수 있고**, 공유 범위는 가입 시 고지된다 | 🟢🔴 | 개인정보 보호법(아동의 정보주체 권리) `확인 필요` + 경쟁사 비교(아이부자는 아이가 범위 선택) | 전체 실시간 공유 | 아동도 정보주체. **1차 설계(전체 공유)를 재검토해야 하는 지점** | R-11 | 아이 화면에서 공유 범위를 조회 가능 |
| P-10 | 퀴즈 정답 오류 발생 시 **신고·정정·재채점 절차**를 제공한다 | 🟢 | **퍼핀 리뷰**("두개다 틀렸다고 해요 고쳐주세요") | 절차 없음 (리뷰 방치) | 교육 서비스의 신뢰 기반. AI 생성 문항일 경우 필수 | R-12 | 신고 접수 → 정정 → 재채점 흐름이 동작 |
| P-11 | 계정 해지 시 **아바타·별·성장 기록의 처리 방식**을 사전 고지한다 | 🔴 | 개인정보 보호법(파기) `확인 필요` | (퍼핀 약관 확인 후 기입) | 아이가 애착을 형성한 자산이라 분쟁 소지가 큼 | R-13 | 해지 화면에 처리 방식이 표시됨 |
| P-12 | 아동 대상 고지는 **아이가 이해할 수 있는 언어**로 별도 제공한다 | 🔴🟢 | 개인정보위 아동·청소년 가이드라인 `확인 필요` | 성인 기준 약관만 확인됨 | 7세도 사용자. 형식적 동의가 아니라 실제 이해 | R-14 | 아동용 고지문 별도 존재 |

### 📌 이 표 쓸 때 규칙

1. **`확인 필요` 표시가 있는 칸은 반드시 원문 확인 후 채운다.** 안 채우면 감점 사유
2. 「퍼핀은 어떻게」 칸은 **약관 원문을 확인한 뒤에만** 적는다. 추측이면 `추정`으로 표기
3. 「우리는 왜 이렇게」 칸이 비면 그 조항은 **버려도 되는 조항**이다
4. 🟢 유형이 절반 이상이면 잘 만든 표. 🔴만 있으면 그냥 법령 나열이라 점수가 안 됨

## 5. 도움말(FAQ)은 제품이다

퍼핀이 실패한 지점을 기준으로 설계합니다. **도움말이 기능이 되는 케이스 4개.**

| 퍼핀의 실패 | 핀프렌즈 도움말 항목 | 근거 |
|---|---|---|
| 카드 발급 전엔 앱을 볼 수 없어 교육 수준 확인 불가 | **가입 전 커리큘럼 공개** — 벌기→쓰기→모으기→불리기 4단계와 문항 샘플 | 리뷰(오하오 2023-05-14) |
| 구독 혜택이 불명확 | **구독 포함/미포함 비교표** | 리뷰(9만원 불만) |
| 별⭐이 뭔지 부모가 이해 못 할 위험 | **"별은 현금이 아닙니다"** — 왜 이렇게 설계했는지 설명 | 1차 규제 방어선 |
| 보상이 현금이라 아이가 학습을 건너뜀 | **"오답이어도 별은 차감되지 않습니다"** — 안심하고 도전하라는 메시지 | 리뷰(류현정 2024-03-28) |

> 💡 도움말이 **"우리 설계 의도를 사용자에게 설명하는 곳"** 이 되면, 그 자체가 Value Proposition 전달 수단입니다.
> 퍼핀은 도움말이 없어서 "과장광고" 소리를 들었습니다.

```
② 각 불만이 어떤 조항의 부재인지 매핑
   → 광고 동의 미분리 / 구독 혜택 미고지 / 사전 안내 부재 / 정정 절차 부재

③ 핀프렌즈 정책 근거 추적표를 보여준다
   → "우리는 12개 조항을 법적 의무·리스크 방어·사용자 가치로 나눠 설계했고,
      전부 PRD 요구사항과 합격 기준으로 추적된다"
```

**한 문장 결론**: 약관은 뒤에 붙이는 게 아니라 처음부터 설계 입력값이다.

1. 법령 **이름만** 가져간다

3. 조항 번호 · 내용 · **최종 개정일**을 원문에서 확인
4. **URL + 확인 날짜**를 기록
