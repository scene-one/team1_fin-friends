# 🧹 미션 (벌기)

4칸 중 **「💰 벌기」** 칸의 실천이다. 아이 화면 표기는 **「벌기」**, 설계 문서상의 이름이 **미션**이다.
*"일하면 돈이 생겨요"* 를 심부름으로 경험하게 한다([[2026-08-31_팀_기능정의-v13|기능정의 v13]] §9).

> 🔴 **[[별-지급-엔진]] 트리거 8종 중 유일한 수동 트리거다.** 나머지 7종은 자동 판정이고,
> 미션만 **부모가 눌러야** 성립한다. 이 페이지의 절반은 그 병목을 다루는 내용이다.

## 한 바퀴

```
① 👪 부모가 등록   미션 내용 + 💵 보상 금액
        ↓
② 🧒 아이가 수행 → 완료 표시 (📷 사진 첨부)
        ↓
③ 👪 부모 「확인하기」 → 사진 확인
        ↓
④ 「칭찬하기」(승인)     「반려하기」        72h 무응답
    ⭐1 + 💵 용돈 충전     ⭐ 미지급 + 사유    ⭐1 + 💵 용돈 충전
                                            + 「확인하지 못했어요」
```

부모 진입 경로는 **아이 통장 화면의 「미션 관리」** — 생성 · 보상 금액 설정 · 확인하기가 한 곳에 있다.

### 등록 주체 — 부모 또는 아이

아이도 미션을 제안할 수 있다. 다만 **부모가 승인해야 활성**된다 — 보상 금액이 실제 돈이기 때문이다.

## 💰 보상은 둘이다 — 용돈과 ⭐

승인 시 아이가 받는 것은 **두 가지**이고, 둘은 [[3층-구조]]의 서로 다른 층에 있다.

| 받는 것 | 무엇 | 어디로 |
|---|---|---|
| 💵 **용돈** | 부모가 미션 등록 시 정한 **보상 금액**(실제 돈) | 아이 지갑 충전 → 쓸 때 [[소비-계획-카드]]로 계획 |
| ⭐ **별 1개** | 즉각 보상 재화 | 옷장([[아바타-옷장]]) |

**둘은 교환되지 않는다** — [[규제-상수]] P-01·P-21. 별로 돈을 살 수 없고 돈으로 별을 살 수 없으며,
그 경로를 **코드에 두지 않는다**.

### 🔴 화면에서 둘을 나란히 두지 않는다

미션 완료 화면은 **⭐를 먼저** 보여주고, 충전된 금액은 **지갑·봉투 화면에서** 확인하게 한다.

> 나란히 두면 아이가 *"별 = 돈"* 으로 학습하고, 그것이 바로 **P-01·P-21이 막으려는 인지**다.
> 규제는 데이터 구조뿐 아니라 **화면 배치에도 걸린다.**

## 📷 사진은 남기지 않는다

아이가 첨부한 사진은 **부모 승인 화면에 표시한 뒤 판정 즉시 파기**한다.
서버에 저장하지 않고 데이터 스키마에 이미지 참조 컬럼을 두지 않는다 — [[규제-상수]] P-13.
**남는 것은 승인 이력뿐**이다.

## ⏱ 승인 병목 — 알림 두 번, 3일 뒤 자동 지급

**부모가 안 봐도 아이는 받는다.** 부모의 미확인이 아이의 손실이 되지 않게 한다.

| 시점 | 처리 |
|---|---|
| 완료 즉시 | 부모에게 **승인 요청 알림 1회** · 부모 화면 **승인 대기 목록**에 등록 |
| **24시간 미승인** | 부모에게 **리마인드 1회** |
| **72시간 미승인** | 🔴 **자동 지급** — **⭐1 + 💵 용돈 충전** 모두 집행 · 「벌기」 실천 +1 |
| 표시 | 🔴 **「칭찬받았어요」가 아니라 「확인하지 못했어요」** — 지급은 하되 **부모가 못 봤다는 사실**은 감추지 않는다 |

**보상은 주되 라벨은 정직하게.** 아이 화면·승인 이력 모두에서 자동 지급 건은
**부모가 누른 건과 시각적으로 구별**된다(`auto=true`). 아이가 잃는 것은 없고,
부모는 자기가 놓친 것을 나중에라도 본다.

> 🔴 **자동 지급 건도 [[WPA-북극성-지표]] 분자에 들어간다.** 아이는 실제로 실천했기 때문이다.
> 다만 `auto=true` 로 **별도 집계**해 `mission_auto_credited` 비율을 **≤ 10%** `[가설]` 로 감시한다
> (`SRS NFR-025`) — 이 값이 곧 **부모가 아이의 실천을 한 번도 안 본 비율**이다.

## 경계 사례

| 상황 | 처리 |
|---|---|
| 보상 **0원** 미션 | 허용 — ⭐와 실천만 기록 |
| 부모 지갑 **잔액 부족** | **⭐와 실천은 정상 지급**, 충전만 보류하고 부모에게 요청 표시 |
| 승인 후 **취소** | ⭐도 충전도 **회수하지 않는다** — 아이가 이미 받은 것을 잃게 하지 않는다 |
| 동일 미션 승인 요청이 **2회 이상** | **⭐는 1회만** · 별 원장 불일치 0건 |
| 부모가 **반려** | ⭐ 미지급 · **「승인되지 않음 + 사유」** 표시 · **「미실천」과 시각적 구별** · 실천 카운트 미가산 |
| 승인 대기 **5건 이상 누적** | **일괄 승인 경로** 제공 · 각 건은 **완료 시각 기준으로 개별 소급** |
| 승인이 **주기 초기화 이후** | ⭐ 지급 · 나무 조건은 주기 N 귀속 · [[월간-숲]] 스냅샷에만 반영 |
| **자동 지급 시 잔액 부족** | ⭐와 실천은 지급, **충전만 보류** — 잔액 부족 규칙과 동일 |
| 자동 지급 **후 부모가 반려하려 할 때** | 🔴 **되돌릴 수 없다** — 승인 후 취소와 같은 원칙. 부모는 **해당 미션을 비활성화**할 수 있을 뿐이다 |
| β 기간 | 🧪 **모의 충전**([[핀프렌즈]] 결제 트랙) |

반려·주기 초기화 2건은 [[측정가능성-리뷰]]가 찾아낸 **스펙 공백**이었다.

## 어디에 반영되나

| 어디 | 무엇으로 |
|---|---|
| [[WPA-북극성-지표]] | 승인된 미션은 **분자에 포함**(WPA-v1 실천 3종 중 하나). 자동 지급 건도 포함하되 `auto=true` 로 별도 집계 |
| [[성장-나무]] | 「벌기」 나무의 **미션 실천 횟수** — 학습·정답과 함께 3종을 모두 채워야 승급. 부모 화면에 **미션 수행률**로 상시 표시 |
| [[학습-커리큘럼-퀴즈]] | 학습 후 **「실천하기」** 화면의 🧹 벌기 칸이 미션이다 |
| [[별-지급-엔진]] | 트리거 **4번** — 8종 중 유일한 수동 |

### 🎬 안 한 칸이 움직인다

「실천하기」 화면에서 **오늘 미션 수행 제출이 0건이면 🧹 벌기 칸이 움직인다**
(상하 바운스 + 기울기 · 2초 간격 · 1회 0.6초 · 실행 즉시 정지).
`prefers-reduced-motion` 설정 시에는 **테두리·배지로 정적 강조**한다.

「잘 쓰기」와 함께 **매일 발생하는 행동**이라 *"오늘 했는가"* 가 정의되는 두 칸이다.
같은 장치가 [[계획-카드-작성-트리거]]의 **두 번째 도달 경로**이기도 하다.

> 🔴 **대가** — 움직임은 주의를 끄는 만큼 소모된다. 매일 같은 방식이면 배너 실명과 같은 둔감화가 온다.
> **애니메이션 노출 대비 실행률**을 감시하고, 4주 실측에서 하락 추세면 강도·주기를 재설계한다.

## 🧭 결정 배경 (Context) — 사진 첨부를 넣고, 사진은 안 남기는 이유

**Summary** 미션은 **앱 밖에서 일어나는 유일한 실천**이다. 판정 근거가 앱 안에 없어서
부모 승인을 두고, 승인의 근거로 사진을 받되 **그 사진을 자산으로 남기지 않는다.**

**Evidence**
- [[별-지급-엔진]] 트리거 8종 중 7종은 앱 내 이벤트로 자동 판정된다 `[설계 확정]`
- 미션만 실물 행동(심부름)이라 앱이 관측할 수 없다 `[설계 확정]`
- 아동 이미지 저장은 [[규제-상수]] P-13이 막는다 `[설계 확정]`

**Implication** 사진은 **판정 순간에만 존재**하면 충분하다. 보관하면 아동 이미지 처리 의무가
통째로 따라붙고, 얻는 것은 사후 분쟁 대비뿐이다. 승인 이력만으로 실천 카운트는 완결된다.

🔴 **받아들인 대가** — 승인 후 분쟁이 생겨도 **되돌아볼 증빙이 없다.** 이 결정은
「승인 후 취소해도 회수하지 않는다」는 규칙에 의존한다. 회수를 도입하면 증빙 필요가 생기므로
**두 결정은 함께 움직인다.**

**기각한 대안** — 사진 서버 보관 후 N일 뒤 파기(*보관 기간 동안 P-13 의무가 그대로 발생*) ·
사진 없이 완료 표시만(*부모가 확인할 근거가 사라져 승인이 형식화*) ·
자동 판정으로 전환(*실물 행동을 관측할 수단이 없다*).

## 🧭 결정 배경 (Context) — 72시간 뒤 자동 지급하는 이유

**Summary** 알림을 **제출 즉시 1회 + 24h 리마인드 1회** 보내고, **72h 미확인이면 ⭐와 용돈을 모두 지급**한다.
표시는 **「확인하지 못했어요」** — 지급하되 부모의 미확인을 감추지 않는다 (`PRD ADR-016` · `SRS FR-032`).

**Evidence**
- 승인 병목은 **아이가 통제할 수 없는 변수**다 — 부모 폰, 부모 습관, [[PWA]] 푸시 도달률(`⬜ 미검증`) `[설계 확정]`
- 미션은 [[별-지급-엔진]] 트리거 8종 중 **유일한 수동**이라, 이 하나만 부모 사정으로 사라진다 `[설계 확정]`
- 보상 금액은 **부모가 미션을 등록할 때 직접 정한 값**이다 — 자동 지급은 새 약속이 아니라 **부모가 이미 한 약속의 집행**이다 `[설계 확정]`
- [[배성우-H2]] 가정은 아이 전용 기기가 없어 알림 도달이 더 나쁘다 — 병목의 부담이 **1차 타깃에 집중**된다 `[관측]`

**Implication** *"했는데 아무 일도 안 일어났다"* 는 경험은 [[외적보상과-내재동기]]가 말하는 **보상 계약의 파기**다.
한 번 겪으면 아이는 다음 미션을 제출할 이유를 잃는다. 병목의 비용을 **아이에게 물리지 않고 시스템이 흡수**한다.

🔴 **받아들인 대가 — 부모 확인 없이 실제 돈이 움직이는 유일한 경로다.**
아이가 미션을 하지 않고 **완료 표시만 눌러도 72시간 뒤 용돈이 들어온다.** 사진은 아무도 안 보고 파기된다.
[[성장-나무]]의 「벌기」도 그만큼 자라므로, 부모가 읽는 **성장 증거의 신뢰도가 자동 지급 비율만큼 희석**된다.

**의존하는 방어선**

| # | 방어선 | 내용 |
|:-:|---|---|
| ① | **부모가 금액을 정했다** | 자동 지급액은 부모가 등록 시 입력한 값 — 시스템이 정하지 않는다 |
| ② | **라벨 분리** | 「확인하지 못했어요」 · `auto=true` — 수동 승인과 이력·화면에서 구별된다 |
| ③ | **잔액 보호** | 부모 지갑 잔액이 부족하면 충전은 보류(잔액 부족 규칙과 동일) |
| ④ | **비율 감시** | `mission_auto_credited` **≤ 10%** `[가설]`(`SRS NFR-025`) · WPA에서 `auto` 별도 집계 |
| ⑤ | **미션 비활성화** | 반복 자동 지급이 보이면 부모가 해당 미션을 끌 수 있다 |

**되돌리는 조건** — `mission_auto_credited / mission_submitted` **> 10%** → **충전만 분리해 보류**하는 안으로 전환
(⭐·실천은 그대로 자동, 돈만 부모 확인). ②~⑤가 무너지면 이 결정 전체가 재검토 대상이다.

**기각한 대안**

| 기각한 안 | 사유 |
|---|---|
| **72h 자동 만료**(⭐ 미지급) | 아이는 했는데 기록이 사라진다 — 병목의 비용을 아이가 낸다 |
| **⭐만 자동, 용돈은 보류** | 아이 입장에서 **보상이 반쪽으로 도착**한다. 부모가 정한 약속의 절반만 집행하는 셈이라 「했으면 받는다」가 흐려진다 *(단, 되돌리는 조건이 발동하면 이 안으로 간다)* |
| **24h 리마인드 제거** | 알림이 1회로 줄면 자동 지급 비율이 올라가고 ④ 감시가 의미를 잃는다 |
| **만료 시간 연장** | 아이 화면이 「기다리는 중」으로 더 오래 막힌다 — O13(≤ 3일)과 충돌 |
| **문자 등 대체 채널 병행** | [[규제-상수]] 동의 범위 밖 · 비용 발생 · MVP 범위 초과 |
