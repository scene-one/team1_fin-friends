# 📝 소비 계획 카드 (F8)

**v0.2에서 유일하게 기능 목록 자체를 바꾼 결정**의 산물. [[PRD_핀프렌즈_v0_2]] §4-2 · 2026-08-21 확정.
우선순위 **Must** · 중요도 5 · 난이도 **5** · Job **J1 + J2**.

## 무엇인가 — 🔄 **봉투형** *(2026-09-01 재정의)*

> **미리 나눠 담고, 쓴 뒤에 어느 봉투에서 빠졌는지 본다.**

| 단계 | 내용 |
|:-:|---|
| **① 봉투 배분** | 충전액을 **용도별 봉투**에 나눠 담는다 — 🍪 간식 · ✏️ 문구 · 🎯 모으기 … |
| **② 결제** | 카드 승인 |
| **③ 자동 대조** | 승인 내역의 **가맹점 업종 → 해당 봉투에서 차감**. 아이가 따로 할 일 없음 |
| **④ 회고** | **두 갈래** — 봉투 안 ⭐1 / 봉투 초과는 회고만 |

**업종을 받는 것이 핵심**이다. 「얼마」만이 아니라 **「어디에」가 데이터로 남는다** → [[대안-대비-벤치마크]] · F13 소비 내역 업종별 집계.
봉투형에서는 **봉투가 곧 업종**이므로 이 대조가 별도 입력 없이 성립한다.

### 🔄 왜 「건별 계획 카드」에서 봉투로 옮겼나

v0.2가 F14·F19를 삭제하면서 **자동 발동이 사라졌다**(아래 참조). 남은 것은 *"아이가 결제 전에 스스로 앱을 열어 적는다"* 는 전제였는데,
**초등 저학년에게 이 전제가 성립하지 않는다.** 알림을 어디에 붙여도 전제 자체는 바뀌지 않는다.

그래서 **상기시키는 방법이 아니라 적는 단위**를 바꿨다 — 결제 건마다가 아니라 **돈이 들어올 때 한 번**.

| | 건별 계획 카드 | **봉투형** |
|---|---|---|
| 적는 시점 | 결제 직전마다 | **충전 시 1회** — 그 기간 전체를 덮는다 |
| 아이 부담 | 매 결제 전 앱 진입 | 배분 1회 + 이후 자동 |
| 작성률 지표 | `plan_card_created ÷ payment_settled` — 🔴 달성 난망 | **배분 완료 여부** — 분모 문제 소멸 |
| 업종 대조 | 계획에 업종을 직접 입력해야 성립 | **봉투 = 업종**이라 입력 없이 성립 |
| C5(충동구매) 신호 | 계획을 안 적으면 신호 자체가 없음 | *"간식 봉투가 비었는데 또 썼다"* 로 **드러난다** |

> 🔑 **근거는 [[배성우-H2]]다.** 현금 봉투를 **3년째** 쓰고 있는 가정이다.
> 새 습관을 요구하는 게 아니라 **이미 하고 있는 행동을 디지털로 옮기는 것**이라 채택률 가정이 훨씬 가볍다.

**제휴사 의존이 없다** — 실제 선불 잔액은 하나로 두고 **앱이 배분만 표시·차감**한다.
카드 한도 제어([[규제-상수]] P-17·P-18, 제휴사 정책 종속)에 기대지 않으므로 제휴 계약 전에도 확정할 수 있다.

### ✏️ 봉투 금액은 나중에 수정할 수 있다

아이가 **언제든 재배분**할 수 있다. *"간식을 줄이고 문구를 늘린다"* 는 판단 자체가 「잘 쓰기」 학습이므로 막지 않는다.

> 🔴 **다만 ⭐ 판정은 결제 시점의 배분 스냅샷으로 고정한다.**
> 그렇지 않으면 **초과 지출 후 봉투를 늘려 「지킴」으로 만드는 우회로**가 열린다.
> 수정은 **다음 결제부터** 적용되고, 재배분 이력은 부모 화면(F13 소비 내역)에 남는다.

| 항목 | 규칙 |
|---|---|
| 수정 주체 | **아이** *(부모는 [[2026-08-31_팀_기능정의-v13|v13]] 갱신 13과 같이 열람만)* |
| 수정 시점 | 제한 없음 |
| 판정 적용 | **결제 시각의 스냅샷** — 소급 없음 |
| 부모 가시성 | 재배분 이력이 소비 내역에 남는다 |

## 🔄 무엇을 대체했나 — F14·F19 삭제

| | 삭제 | 대체 |
|---|---|---|
| **F14** 📍 위치 알림 (3분 체류 · 온디바이스) | ❌ | **F8 계획 카드** |
| **F19** 🚦 소비 사전 개입 2차 트리거 | ❌ | **F8 계획 카드** |

v0.1에서 F19 배치는 **최상위 미결**(옵션 A 유지 / B 경량 분할 / C Must 승격)이었다.
**셋 다 채택하지 않고 넷째 안으로 확정** — *자동 트리거를 만들지 않고, 사전 개입을 「쓰기 전에 적는 행위」로 옮긴다.*

### 왜 삭제했나 — 선결 조건 4개 중 3개가 미해결이었다

| # | 선결 조건 | 상태 |
|:-:|---|:-:|
| ① | 아이 기기 전제 (키즈워치·부모 폰 공유에서 알림 수신) | 🔴 미해결 — **선별 인물 둘 다 전용 스마트폰이 없다** ([[배성우-H2]]의 아이는 키즈워치) |
| ② | 3분 임계값의 근거 (체류시간 실측) | 🔴 미해결 |
| ③ | [[규제-상수]] P-19 준수 방식 (좌표 미저장 → 온디바이스 판정) | 🔴 미해결 |
| ④ | 온라인 결제 개입 수단 | 🔴 미해결 |

> **그리고 ②는 해결해도 소용이 없었다** — **3분 트리거가 못 잡는 소비가 곧 C5** 였으므로, F14를 승격해도 선별 Pain이 남는다.

### 계획 카드는 넷을 전부 우회한다

| | F14 / F19 | **F8 계획 카드** |
|---|---|---|
| 기기 조건 | 🔴 스마트폰 + 백그라운드 위치 권한 + 알림 | ✅ **무관** — 부모 폰에서도 적을 수 있다 |
| 위치정보 | 🔴 수집·온디바이스 판정 (P-19) | ✅ **아예 안 씀 → P-19 적용 없음** |
| 검증 선행 | 🔴 체류시간 실측 필요 | ✅ **불필요** |
| 남는 데이터 | 알림을 봤다 / 안 봤다 | ✅ **업종 × 금액 대조** — 검증 가능한 행동 데이터 |

이 결정으로 **리스크 R2(아이 기기 전제)가 해소**됐다.

## 🔴 대가 — 정직하게 남긴 것

| 잃은 것 | 내용 |
|---|---|
| **자동 발동이 사라졌다** | 위치 알림은 아이가 아무것도 안 해도 울렸지만, 계획 카드는 **먼저 적어야** 작동한다. 사각지대가 없어진 게 아니라 **「3분 미만 소비」에서 「계획을 적지 않은 소비」로 옮겨갔다** |
| **C10·C12가 완전 미대응이 됐다** | 온라인 결제·FOMO 3초 판단은 F19 하나에 걸려 있었고 이제 **대응 기능이 0개**다. 온라인 결제는 계획 카드를 적을 **계기조차 없다** |
| **대외 문구를 바꿔야 한다** | *"매장에 3분 이상 머무르면 알림"* 은 **더 이상 사실이 아니다.** 발표·자료에서 지오펜싱 서술을 전부 내릴 것 → [[인용-금지-목록]] |

## 🔑 생존 조건 — 🔄 **봉투 배분율** *(2026-09-01 지표 교체)*

원래 생존 조건은 **결제 건 대비 계획 카드 작성률 ≥ 50%** 였다. 봉투형으로 옮기면서 **분모가 바뀐다.**

> **충전 건 대비 봉투 배분 완료율 ≥ 80%.**
> 미달이면 사전 절반이 비고, **대조할 것이 없어 사후 절반까지 무너진다** — 실패 방식은 같다.

| 코드 | 지표 | 비고 |
|---|---|---|
| **O7** *(개정)* | `envelope_allocated` ÷ `wallet_topped_up` | 🔄 분모가 **결제 건수 → 충전 건수** |
| **E3** *(개정)* | PASS ≥ 80% / HOLD 60~79% / **FAIL < 60% → 배분 UX 재설계 · C5 발생률 재산출** | 기준선이 오른 이유는 아래 |
| **US-4 AC4** | MVP 운영 4주 실측 | 그대로 |

> ⚠️ **왜 50%가 아니라 80%인가** — 행위 빈도가 낮아졌기 때문이다.
> 결제마다 적는 구조에서 50%는 *"두 번 중 한 번"* 이지만, 충전 때 한 번 나누는 구조에서 50%는
> *"충전의 절반이 용도 없이 들어간다"* 는 뜻이라 훨씬 나쁘다. **행위가 드물어질수록 기준선은 올라야 한다.**

🔴 **이 두 숫자는 전부 `[가설]`이다.** 봉투 배분율의 기준선은 `⬜ 미측정`이며,
MVP 4주 실측 전까지 어떤 값도 성과로 인용할 수 없다 → [[인용-금지-목록]].

판정 규칙은 [[PASS-HOLD-FAIL-3구간-판정]].

## 두 갈래 회고 — C6 대응

> **보상의 존재 여부가 아니라 보상이 무엇에 연결되어 있는가가 문제다** ([[외적보상과-내재동기]]).
> 여기서 ⭐는 「소비했다」가 아니라 **「나눠 담은 대로 썼다」** 에 연결된다.

⭐를 **계획 준수 시에만** 지급하도록 확정(v13 §5)해서 *"참은 날 = 안 참은 날"* 문제는 해소됐다.

| 갈래 | 조건 | ⭐ | 기록 |
|:-:|---|:-:|---|
| **A 지킴** | 결제액이 **해당 봉투 잔액 이내** *(결제 시점 스냅샷 기준)* | **⭐1 지급** | `plan_met=true` · `star_granted=true` |
| **B 넘김** | 결제액이 **봉투 잔액을 초과** | **미지급** *(보유 별 차감 없음 — P-03)* | `plan_met=false` · `star_granted=false` |

🔴 **갈래 B의 이탈 감시**가 남은 위험이다 — 보상 없는 쪽 회고가 방치되면 **「행동」 데이터가 실패한 날만 비게 된다.**
AC2-3: 계획 초과 건의 회고 열람률이 **계획 준수 건 대비 ≥ 70%**.

### 🔴 갈래 B 이탈 방지 — **회고를 ⭐가 아니라 다음 배분에 잇는다** *(2026-09-01 확정 · MINOR)*

보상 없는 쪽(넘김) 회고가 방치되면 **「행동」 데이터가 실패한 날만 비게 된다.**
AC2-3은 계획 초과 건의 회고 열람률이 **계획 준수 건 대비 ≥ 70%** 를 요구한다. 그 70%를 무엇으로 받칠 것인가.

> **⭐를 붙이지 않는다.** 붙이는 순간 *"넘겨도 별을 받는다"* 가 되어 [[소비-계획-카드]] 갈래 A·B 구분이 무너진다.
> 대신 **회고를 다음 봉투 배분의 입구로 만든다.**

| | 처리 |
|---|---|
| 넘긴 뒤 화면 | *"🍪 간식 봉투를 1,200원 넘겼어요. 다음 주에는 얼마로 할까요?"* → **바로 배분 화면** |
| ⭐ | ❌ 없음 (변경 없음) |
| 부모 화면 | 넘김 건과 **재배분 이력**이 소비 내역에 나란히 남는다 |

**왜 이게 열람률을 받치나** — 회고가 *"끝난 일을 되돌아보는 화면"* 이면 열 이유가 없지만,
**다음 주 내 돈을 정하는 입구**면 열 이유가 생긴다. 보상이 아니라 **효용**으로 끄는 방식이다.

> ⚠️ **대가** — 넘긴 직후에 재배분을 권하는 것은 *"넘겼으니 예산을 늘려라"* 로 읽힐 수 있다.
> 문구는 **늘리는 방향을 권하지 않고 「얼마로 할까요」로 열어두는** 중립형으로 쓴다.
> AC2-3 열람률이 4주 실측에서 70% 미달이면 이 설계를 재검토한다.

## ✅ 봉투 경계의 성격 — **표시용 구획이지 지갑이 아니다** *(2026-09-01 확정)*

> **결제 순간 봉투가 비어도 카드는 막히지 않는다. ⭐만 지급되지 않는다.**

봉투는 **판정 기준**이고, 실제 선불 잔액은 하나다. 남는 것은 *"어느 봉투를 넘겼다"* 는 기록이다.

| 상황 | 결제 | ⭐ | 기록 |
|---|:-:|:-:|---|
| 봉투 잔액 이내 | ✅ | **⭐1** | `plan_met=true` |
| 봉투 초과 · 전체 잔액은 있음 | ✅ **통과** | ❌ | `plan_met=false` · **어느 봉투를 얼마나 넘겼는지** |
| 전체 잔액 부족 | ❌ *(제휴사 잔액 판정)* | ❌ | — |

### 왜 막지 않기로 했나

**① 이 제품은 아이를 벌하지 않는 쪽을 일관되게 택해왔다.**
[[규제-상수]] P-03 — *"계획을 넘겨도 보유 별을 차감하지 않는다"*. 봉투를 넘었다고 결제를 막는 것은
그 원칙과 어긋난다. 미지급은 **보상의 부재**지만 결제 차단은 **제재**다 → [[외적보상과-내재동기]].

**② 「명시적으로 옮기게 하기」는 기각된 전제로 되돌아간다.**
아이가 매장 앞에서 앱을 열어 봉투를 옮겨야 한다면, 그것은 [[소비-계획-카드]]가 봉투형으로 옮겨오며
기각한 바로 그 전제(*"결제 직전에 스스로 앱을 연다"*)다.

**③ 진짜 차단은 우리 권한이 아니다.**
카드 이용한도·업종 제한은 **제휴사 정책 종속**이다([[규제-상수]] P-17·P-18).
봉투 단위 차단을 구현하려면 제휴 계약이 선행돼야 하므로 지금 확정할 수 없다.

> 🔴 **받아들인 대가** — 봉투가 「무를 수 있는 약속」이 된다. 아이가 매번 넘겨도 잃는 것은 ⭐뿐이고,
> 봉투 구조가 **잔소리 없는 가계부**로만 남을 수 있다. 이 위험은 갈래 B 회고 열람률(**≥ 70%**)이 감시한다 —
> 넘긴 날의 회고가 방치되면 봉투는 실제로 아무 힘이 없는 것이다.

## 🧭 결정 배경 (Context) — 왜 봉투형인가

**Summary**
「어떻게 상기시킬까」라는 프레임을 기각하고 **적는 단위**를 바꿨다. 결제 건별 계획 카드 → 충전 시 용도별 봉투 배분.

**Evidence**
- [[배성우-H2]] — **현금 봉투 주 5,000원 · 3년** `[관측]`. 대체재 한계는 *"볼 것이 없다"*(Satisfaction 1 · **기록 0건**)이지 봉투라는 방식이 아니었다.
- v0.2가 F14·F19를 삭제하며 **자동 발동이 사라졌다**고 스스로 기록했다 `[설계 확정]`.
- 남은 전제는 *"아이가 결제 직전에 스스로 앱을 연다"* 였고, [[학습-난이도-5단계]] ③ 시간 지평 축이 **만 7세는 「다음」을 잡기 어렵다**고 지적한다 `[A]`.
- 원 지표 O7 = `plan_card_created ÷ payment_settled` — **결제마다 작성**을 요구한다.

**Implication (영향 및 판단 이유)**
- 상기 수단(알림·배너·푸시)을 어디에 붙여도 **전제 자체는 안 바뀐다.** 그래서 수단이 아니라 단위를 바꿨다.
- **방식은 이미 작동 중이고 없던 것은 기록뿐**이라는 구분이 결정의 축이다 — 새 습관을 요구하지 않으므로 채택률 가정이 가벼워진다.
- 부수 효과 3가지 — ① O7의 무리한 분모 소멸 ② **봉투 = 업종**이라 업종 대조가 입력 없이 성립 ③ 제휴사 한도 API([[규제-상수]] P-17·P-18) 의존 제거.
- 대가 — F8의 서사가 「가기 전에 적는다」에서 「미리 나눠 담는다」로 이동했고, **새 기준선 80%도 전부 `[가설]`** 이다.

### 기각한 대안

| 안 | 기각 이유 |
|---|---|
| 정기 시각 알림 | 소비 없는 날에도 울려 **무시를 학습**시킨다 |
| 홈 상시 배너 | 매일 노출돼 배너 실명(banner blindness) |
| 충전 시점 푸시 | 계기는 자연스러우나 **부모 행동에 종속**되고 충전이 드물면 트리거도 드물다 |
| 결제 직후 회고 유도 | 사후 학습이라 **선별 Pain C5(사전 개입)** 자체를 못 잡는다 |
| 결제 게이트(기본 잠금) | 작성률을 구조적으로 100%로 만들지만 **제휴사 한도 API 종속**이라 계약 전 확정 불가 |

> 🔁 위 기각안들을 **조건부(상태·이벤트 기반)로 재설계**하면 기각 사유를 피할 여지가 있다 — 현재 결정을 뒤집는 것은 아니고, E3 미달 시 재검토 참고용 비교안 → [[건별-계획-알림-대안설계]].

## 선결 과제 순서

```
① 결제 매칭 검증 (업종 매칭 정확도 ≥ 90% · US-4 AC2)
   → ② 봉투 배분율 실측 (MVP 4주 · E3 개정)
      → ③ 갈래 B 회고 열람률 감시 (≥ 70% · AC2-3)
```

**①③ 모두 카드 업종 코드가 실제로 어떻게 매겨지는지에 달려 있다** → [[카드-업종-분류-MCC]]. 특히 PG/간편결제 구간은 업종이 구조적으로 뭉뚱그려져, 매칭 정확도 미달·억울한 미지급이 **아이의 행동 문제가 아니라 데이터 한계**일 수 있다.

**①②를 먼저 두는 이유** — 둘 다 문항이 아니라 **계측**이고, 결과가 F8의 성립 여부를 직접 바꾼다.
①이 실패하면 대조 화면이 신뢰를 잃고, ②가 실패하면 대조할 것이 없다.

🔴 **봉투형에서 ①의 무게가 더 커졌다.** 건별 계획 카드는 아이가 업종을 직접 골랐지만,
봉투형은 **가맹점 업종 코드가 봉투를 자동 결정**한다. 매칭이 틀리면 아이가 안 쓴 봉투에서 돈이 빠지고,
그것은 **아이가 모은 것을 잃는 경험**이라 [[별-지급-엔진]]의 정합성 원칙과 같은 무게로 다뤄야 한다.
가맹점 분류 상세도는 **제휴 계약 확인 사항**이다([[규제-상수]]).

## 🧭 실무 제안 — 봉투 배분을 실제로 언제 하게 만들 것인가 `[제안]`

⚠️ 팀 결정이 아니라 이 질문에 답하며 정리한 **제안**이다. **②(봉투 배분율 실측)가 무엇에 달려 있는지에 대한 답**이며, E3 FAIL 시 재설계 대상인 「배분 UX」의 구체안이기도 하다.

**출발점 — 「기각한 대안」이 알림 자체를 막은 게 아니라 *상시성*을 막았다.** 정기 시각 알림(상태 무관 반복)·홈 상시 배너(항상 노출)·충전 시점 푸시(기기 종속)가 기각된 공통 이유는 **조건 없이 계속 울리거나 뜬다는 점**이다. 반대로 **미해결 상태에서만 나타나고 해결하면 사라지는 신호**는 같은 범주가 아니다.

| 장치 | 내용 | 왜 기각된 것들과 다른가 |
|---|---|---|
| **홈(옷장) 화면 상태 신호** | 미배분 충전이 있을 때만 아바타 옆에 표시(동전 주머니 등) | 상시가 아니라 **미해결 상태에만** 존재 — 처리하면 사라진다 |
| **「실천하기」 잘쓰기 칸 배지** | 앱 아이콘 배지 패턴(숫자·점) | 이미 학습 완료 후 실천하기로 자동 이동하는 기존 동선 안에서 마주친다 — 새 진입점을 만들 필요가 없다 |
| **1회성 환영 모달** | *"용돈이 도착했어요! 나눠 담아볼까요?"* — 충전 이벤트당 정확히 1번 | 스케줄이 아니라 **이벤트에 귀속**돼 반복되지 않는다 |

**푸시 알림은 주 장치로 쓰지 않는다.** [[배성우-H2]] 페르소나(키즈워치·부모 폰 공유)에서 기기가 푸시를 못 받는 경우가 이미 확인돼 있어 — 대신 **출석 ⭐(앱 실행만으로 별 1개, [[별-지급-엔진]])가 이미 재방문을 유인**하고 있으므로, 다음 접속 시 위 상태 신호를 마주치게 하는 쪽이 기기 의존이 없다.

**배분 UI는 숫자 입력이 아니라 동전을 봉투로 옮기는 조작으로.** [[학습-난이도-5단계]]가 지적한 비율·퍼센트 어려움을 피하고, "해야 할 일"이 아니라 "잠깐 만지는 것"으로 느껴지게 한다.

> 🔴 **배분 완료 자체에는 ⭐를 붙이지 않는다.** 갈래 A(지킴)의 ⭐와 겹치면 [[3층-구조]]가 지켜 온
> **"별은 양, 나무는 질"** 구분이 흐려진다. 즉각 피드백은 애니메이션·효과음 정도로 제한한다.
