# PWA — [[핀프렌즈]]의 앱 전달 방식

**2026-09-01 확정.** 부모 앱·아이 앱을 **네이티브가 아니라 웹으로** 만들고 설치를 생략한다.
[[2026-08-31_팀_기능정의-v13|기능정의 v13]] §16이 **three.js** 만 확정하고 *"나머지 스택은 범위 밖"* 이라 남긴 자리를 채운다 — 스택 전체 현황은 [[기술-스택]].

## 왜 웹인가

| 근거 | 무엇이 좋아지나 |
|---|---|
| **three.js가 자연 서식지다** | 아바타·공간 키트·펫의 glTF 렌더링이 브라우저 네이티브. WebView 브릿지가 필요 없다 |
| 🔑 **[[핀프렌즈]] 초대 링크와 맞물린다** | 페어링 링크를 열면 **설치 없이 바로 연결**된다. S12가 흡수하려던 마찰이 아예 사라진다 |
| **앱 2개 부담이 줄어든다** | 부모용·아이용을 **경로/서브도메인으로 분리**해 한 코드베이스에서 배포. 4인 팀에 현실적 |
| **배포가 즉시** | 스토어 심사가 없어 β 4주 운영 중 수정이 당일 반영된다 |

## 🔴 P-05 차단을 무엇으로 보증하는가

웹에는 네이티브 앱 같은 빌드 산출물 경계가 없다. **오리진으로 같은 보증을 만든다:**

> **부모용·아이용을 서로 다른 오리진(서브도메인)에 둔다.**
> 아이 오리진의 번들에 부모 API 클라이언트를 포함하지 않고, **서버가 오리진별로 스코프를 강제**한다.
> 검증은 *"아이 오리진 번들에 부모 엔드포인트 문자열 0건"* + *"아이 토큰으로 부모 API 호출 시 403"* 으로 한다.

→ [[규제-상수]] P-05·P-22

## 🔴 받아들인 대가

| # | 내용 |
|:-:|---|
| **1** | 🔴 **부모 신뢰도.** 스토어에 없는 서비스에 아동 금융 정보를 맡기는 데 저항이 있을 수 있다. 1차 타깃이 [[배성우-H2]]형(아날로그 가정)이라 **디지털 신뢰 장벽이 특히 높은 집단**이다. `[가정]` — SRS §7.1 β 인터뷰에서 물어야 한다 |
| **2** | 🔴 **푸시 알림 제약.** iOS 웹 푸시는 홈 화면 추가를 전제한다. F11(3일 미접속 알림)뿐 아니라 **[[계획-카드-작성-트리거]]의 급소**가 여기다 — 알림이 안 닿으면 남는 경로가 화면 애니메이션 하나뿐이다 |
| **3** | **3D 성능 편차.** 저사양 안드로이드에서 three.js 프레임이 떨어질 수 있다. 성능 SLO가 *"잠정 상한"* 인 이유가 여기서 더 커진다 |
| **4** | **오프라인 처리.** [[별-지급-엔진]] AC-E의 *"오프라인 후 재연결 시 중복 지급 0건"* 을 Service Worker로 직접 구현해야 한다 |

## 함께 정해진 것

- **외부 CDN을 쓰지 않고 정적 자산을 자체 호스팅**한다 — 아동 개인정보 서비스에서 제3자 오리진 호출을 줄이기 위해서다(NFR-008·009).
- 접속 ⭐([[별-지급-엔진]] 트리거 2)의 정의는 **아이 오리진 세션 시작**으로 유지된다.
