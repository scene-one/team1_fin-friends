# wiki/ — LLM이 쓰고 유지하는 지식베이스

`raw/` 가 원본이라면 여기는 **컴파일된 결과물**입니다. 사람은 읽고, LLM이 씁니다.
새 원본이 들어올 때마다 LLM이 관련 페이지를 **전부 갱신**합니다 — 원본 1건이 보통 위키 페이지 10~15개를 건드립니다.

## 카테고리를 나눈 기준 — **「이 페이지가 답하는 질문」 하나**

폴더는 *"이게 무슨 종류의 글이냐"* 가 아니라 **"읽는 사람이 무엇을 알고 싶어 왔느냐"** 로 나눕니다.
번호는 **읽는 순서**입니다 — 위에서 아래로 읽으면 제품이 왜 이렇게 생겼는지 한 바퀴가 됩니다.

| 폴더 | 답하는 질문 | 들어가는 것 |
|---|---|---|
| **`10-제품/`** | 핀프렌즈는 **무엇인가** | 서비스 전체상 · 가치 선언 · 3층 구조 · 북극성 지표 · 수익 구조 · 전달 방식 |
| **`20-기능/`** | 화면에서 **무엇을 하는가** | 기능 1개 = 페이지 1장. 미션 · 소비 계획 카드 · 위시리스트 · 예적금 · 학습·퀴즈 · 별 · 나무 · 숲 · 옷장 |
| **`30-사용자/`** | **누구의 어떤 문제**인가 | 페르소나 · 고객 문제(Pain) |
| **`40-시장/`** | **누구와 겨루는가** | 경쟁 서비스 · 사업자 · 규제·조사 기관 · 벤치마크 |
| **`50-이론/`** | **왜 그렇게 만드는가** | 학술 근거 · 금융교육 이론 · 외부 지식 |
| **`60-규칙/`** | **무엇을 넘으면 안 되는가** | 규제 상수 · 인용 금지 · 증거 등급 · 판정 규칙 |
| **`70-원본요약/`** | 그 근거의 **원본은 무엇인가** | `raw/` 1건 = 요약 1장 |
| **`80-종합/`** | 질문 하나에 **위키 전체로 답하면** | 질의에 답하며 만든 분석 |

### 헷갈릴 때 — 세 가지 갈림길

| 갈림길 | 판정 |
|---|---|
| `10-제품` vs `20-기능` | **화면 하나로 좁혀지면 `20-기능`.** 아이나 부모가 만지는 것이 아니면 `10-제품` |
| `30-사용자` vs `40-시장` | **우리가 위하는 쪽이면 `30-사용자`, 우리가 겨루는 쪽이면 `40-시장`** |
| `50-이론` vs `60-규칙` | **어겨도 되면 `50-이론`, 어기면 안 되면 `60-규칙`** |

> 🔴 **페이지 이름은 사람이 부르는 이름으로 씁니다.** 검색은 제목을 먼저 맞춥니다 —
> 팀이 「미션」이라 부르는 기능의 페이지 이름이 `별-지급-엔진` 이면 아무도 못 찾습니다.
> 내부 코드명(F2·F12)은 제목이 아니라 `tags` 와 본문에 둡니다.

## 구조

```
wiki/
├─ index.md          # 전체 카탈로그 — 수집할 때마다 갱신
├─ log.md            # 시간순 기록 (추가 전용)
├─ 10-제품/
├─ 20-기능/
├─ 30-사용자/
├─ 40-시장/
├─ 50-이론/
├─ 60-규칙/
├─ 70-원본요약/      # 하위 폴더는 raw/ 를 그대로 미러링한다
└─ 80-종합/
```

### `70-원본요약/` 만 규칙이 다릅니다

여기는 **`raw/` 의 폴더 구조를 그대로 미러링**합니다. 매핑이 규칙 하나로 끝나게 하기 위해서입니다:

```
raw/60-internal/prd/PRD_핀프렌즈_v0_2.md
  → wiki/70-원본요약/60-internal/prd/PRD_핀프렌즈_v0_2.md
```

그래서 이 폴더 안쪽만 `10-market` · `60-internal` 같은 **raw 쪽 이름**을 씁니다. 의도된 예외입니다.
`00-inbox/` 는 미분류 임시 폴더라 짝이 없습니다 — 수집 시 카테고리로 옮긴 뒤 요약합니다.

## 작성 규칙

- **링크는 위키링크** `[[페이지-이름]]` 로 씁니다. 아직 없는 페이지를 가리켜도 됩니다 — 나중에 쓸 거리라는 표시입니다.
- **모든 주장에는 출처를 답니다.** `[[원본요약-페이지]]` 를 가리키고, 원본 요약 페이지가 `raw/` 실제 파일 경로를 적습니다.
- **모순은 지우지 말고 표시합니다.** 새 자료가 기존 주장과 충돌하면 양쪽을 남기고 ⚠️ 로 표시한 뒤 어느 쪽이 더 신뢰할 만한지 근거를 답니다.
- **프론트매터**를 답니다:
  ```yaml
  ---
  title: 미션 (벌기)
  description: "F2 「벌기」 — 부모가 등록하고 아이가 수행, 부모 승인 시 용돈과 별 1개"
  type: 기능              # 폴더 이름과 같게 (제품·기능·사용자·시장·이론·규칙·원본요약·종합)
  updated: 2026-09-01
  sources: 2              # 이 페이지를 뒷받침하는 원본 수
  tags: [F2, 벌기, 실천]
  ---
  ```
  `title` 은 **사람이 부르는 이름**, `description` 은 **한 줄 요약**입니다.
  둘 다 사이트 상단과 검색 결과에 그대로 노출되므로 비워 두지 않습니다.

## 확장 규칙

- 한 폴더가 30개를 넘으면 **하위 폴더를 만들지 말고 새 번호대를 만듭니다** — 2단 중첩은 탐색을 어렵게 합니다.
  (예외는 `70-원본요약/` 뿐이고, 거기는 `raw/` 를 따릅니다.)
- 번호 사이는 비워 둡니다 — `25-` 처럼 끼워 넣을 수 있게.
- `index.md` 가 너무 길어지면 카테고리별 `index.md` 로 쪼개고 루트 `index.md` 는 목차만 남깁니다.
