# wiki/ — LLM이 쓰고 유지하는 지식베이스

`raw/` 가 원본이라면 여기는 **컴파일된 결과물**입니다. 사람은 읽고, LLM이 씁니다.
새 원본이 들어올 때마다 LLM이 관련 페이지를 **전부 갱신**합니다 — 원본 1건이 보통 위키 페이지 10~15개를 건드립니다.

## 구조

```
wiki/
├─ index.md      # 전체 카탈로그 (내용 지향) — 수집할 때마다 갱신
├─ log.md        # 시간순 기록 (추가 전용) — 수집·질의·린트 이력
├─ concepts/     # 개념·이론·기획 프레임
├─ entities/     # 고유명사 — 서비스·기업·기관·인물·기술
└─ sources/      # 원본 1건 = 요약 페이지 1장 (raw/ 와 1:1 대응)
```

### `concepts/` — 개념·이론·기획

| 하위 폴더 | 담는 것 |
|---|---|
| `product/` | 제품 기획 개념 — 기능 정의, UX 원칙, 페르소나, 고객여정 |
| `finance-education/` | 금융교육 이론 — 용돈교육, 저축습관 형성, 금융이해력 |
| `behavior-reward/` | 행동·보상 이론 — 내적/외적 동기, 게이미피케이션, 습관 형성 |
| `business-strategy/` | 사업 프레임워크 — Five Forces, 가치사슬, TAM-SAM-SOM, JTBD |
| `tech/` | 기술 개념 — 아키텍처 패턴, 데이터 모델 |

### `entities/` — 고유명사

| 하위 폴더 | 담는 것 |
|---|---|
| `services/` | 퍼핀, 아이부자, 카카오뱅크 mini, 토스 유스카드, 핀프렌즈 |
| `companies/` | 서비스 운영사 — 하나은행, 카카오뱅크, 비바리퍼블리카 |
| `organizations/` | 조사·규제 기관 — 금융감독원, OECD, 윤선생, Dataintelo |
| `people/` | 연구자·인용된 인물 |
| `tech-stack/` | 프레임워크·라이브러리·API |

### `sources/` — 원본 요약

**`raw/` 의 번호 폴더를 그대로 미러링합니다.** 매핑이 규칙 하나로 끝나게:

```
raw/30-research/2024_ETRD_게이미피케이션-메타분석.pdf
  → wiki/sources/30-research/2024_ETRD_게이미피케이션-메타분석.md
```

`00-inbox/` 는 미분류 임시 폴더라 `sources/` 에 짝이 없습니다 — 수집 시 카테고리로 이동한 뒤 요약합니다.

## 작성 규칙

- **링크는 위키링크** `[[페이지-이름]]` 로 씁니다. 아직 없는 페이지를 가리켜도 됩니다 — 나중에 쓸 거리라는 표시입니다.
- **모든 주장에는 출처를 답니다.** `[[sources/30-research/...]]` 로 원본 요약 페이지를 가리키고, 원본 요약 페이지가 `raw/` 실제 파일 경로를 적습니다.
- **모순은 지우지 말고 표시합니다.** 새 자료가 기존 주장과 충돌하면 양쪽을 남기고 ⚠️ 로 표시한 뒤 어느 쪽이 더 신뢰할 만한지 근거를 답니다.
- **프론트매터**를 답니다 (Obsidian Dataview 용):
  ```yaml
  ---
  title: 퍼핀
  type: entity/service
  updated: 2026-08-31
  sources: 4
  tags: [경쟁서비스, 국내]
  ---
  ```

## 확장 규칙

- 한 폴더가 150개를 넘으면 하위 분할하고, `sources/` 는 `raw/` 와 **같은 축으로** 나눕니다.
- `index.md` 가 너무 길어지면 카테고리별 `index.md` 로 쪼개고 루트 `index.md` 는 목차만 남깁니다.
- 페이지 수가 수백 단위를 넘어 `index.md` 만으로 탐색이 안 되면 로컬 검색 도구 도입을 검토합니다.
